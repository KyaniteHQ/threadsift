## Majors

### The ten settings are restated in five lists, and the one link that matters, setting to attribute, lives in none of them
- `library.js:81` `var LOOK_KEYS = ['font', 'width', 'density', 'comments', 'accent', 'tags', 'images'];` beside `library.js:79` `SETTING_KEYS`, `library.js:83` `SETTINGS_DEFAULT`, `Library.dc.html:327-329` `function lookAttrs(set) { return { font: set.font, width: set.width, ... images: set.images ? 'on' : 'off' }; }`, and the template attributes at `Library.dc.html:210` `data-font="{{look.font}}" data-width="{{look.width}}" ... data-images="{{look.images}}"`.
- Reset look has one definition of the keys that it resets (`LOOK_KEYS`, used only by `resetLook`, `Library.dc.html:382`). I ran it: from Grid, Sheet, Dark, Mono, Wide, Roomy, Cards, Rust, Chips, images Off, Reset look left `layout`, `openAs` and `theme` alone and put the other seven at the defaults. But the same seven keys are written again in `lookAttrs`, in the 7 attributes of the template, in the tooltip text `Settings.dc.html:89` ("Font, text width, density, comment style, accent, tag style and card images go back..."), and in the `tokens.css:9-11` header. Nothing ties these together: add an eighth look setting and you edit `SETTINGS`, `SETTING_KEYS`, `SETTING_GROUPS`, `LOOK_KEYS`, `SETTINGS_DEFAULT`, `lookAttrs`, the template, a `tokens.css` block and the tooltip. A key missing from `lookAttrs` silently does nothing; one missing from `LOOK_KEYS` silently survives Reset. Images is the odd one: its option ids are booleans (`library.js:57`), so `settingValue` has a `k === 'images'` branch (`:97`), `toBit` a boolean branch (`:130`) and `lookAttrs` a ternary (`:328`), all to turn `true` into the `on` that `tokens.css:156` needs.
- Cost: this is the contract between the settings panel and `tokens.css`, and a rebuilder has to assemble it from 3 files. `tokens.css` never names its plain options either (`plex`, `medium`, `compact`, `lines`, `cobalt`, `dots`, `on`): they exist only as the first words of `SETTINGS_DEFAULT`, so nobody can check that the plain block and the default id still agree.
- Simpler structure, as an instruction to Claude Design: "Give each entry of `SETTINGS` in `library.js` its own `attr` (for example `font: { label, kind, options, attr: 'data-font', default: 'plex' }`; `null` for Layout, Open items as and Theme). Build `SETTING_KEYS`, `LOOK_KEYS` (the entries that have an `attr`), `SETTINGS_DEFAULT` and `lookAttrs` from that one table in a loop, and delete the four hand-written lists. Make the Images ids the strings `'on'` and `'off'` so the stored value, the option id and `data-images` are the same word, and delete the boolean branches in `settingValue`, `toBit` and `lookAttrs`. Build the Reset look tooltip from the labels of `LOOK_KEYS`. In `tokens.css`, write the id of the plain option in each look block's comment (`/* plain: plex */`)." This deletes 4 lists, 3 special-case branches and one string that can drift. Reaches only into the files already in the range.

## Minors

### The sheet's side buttons have a measured fallback that cannot run
- `Library.dc.html:456-461` `if (b.left < a.left || b.right > r.left) this.setState({ sidesAt: this.state.width });` with `:471` `if (R.nav === 'sides' && this.state.sidesAt === w) R.nav = 'bar';` and `:445` `this.checkSides();`
- Cost: item 12 asked for the buttons to move into the bar when the gap beside the sheet is under 56px. The gap is `--side-gap: 72px` (`tokens.css:176`) and the buttons need `--target + --s3` = 56px (`Library.dc.html:198-199`), so the CSS always leaves 16px. I measured the Grid Sheet at app widths 761, 800, 880, 905, 1000 and 1440: `.side-prev` started at 16, 16, 16, 17, 64 and 284px, never left of the app, and `sidesAt` never fired. Meanwhile every `componentDidUpdate` runs 3 `getBoundingClientRect` calls, `rules()` (used by keys, focus, settings and rendering) carries a width-keyed override, and a reader has to learn a fallback that does not happen.
- Simpler structure, as an instruction to Claude Design: "Delete `checkSides`, the `sidesAt` state and the `R.nav = 'bar'` line in `rules()`. Write `--side-gap` in `tokens.css` as `calc(var(--target) + var(--s3) + var(--s4))` so the 56px the buttons need is part of the token, and say so in its comment."

### The accent colour formula is written four times, and the swatch needs its own copy
- `tokens.css:186` `--acc: oklch(var(--acc-l) var(--acc-c) var(--ah));` again at `:197` and `:209`, and `Settings.dc.html:54` `background: oklch(var(--acc-l) var(--acc-c) var(--ah));`
- Cost: the three theme blocks differ only in `--acc-l` and `--acc-c`, so the formula in each is the same text. The swatch cannot use `--acc` because `--acc` is computed on the app root before the swatch's `data-accent` changes `--ah`, so Settings repeats the formula. A change to how the accent is built (say, adding a gamut clamp) has four places to edit.
- Simpler structure, as an instruction to Claude Design: "Delete `--acc: oklch(...)` from the three theme blocks. Declare it once in the 'worked out' block `:root, .app, [data-font]` of `tokens.css:160`, and add `[data-accent]` to that selector list, so any element with `data-accent` works out its own `--acc`. Then `.st-sw` becomes `background: var(--acc)`."

### Theme, Layout and Open items as are classes, the other seven settings are attributes, and the class names are not the setting ids
- `Library.dc.html:841` `cls: ['app', 'L-' + D.list, 'R-' + D.reader, 'th-' + theme, st.vt ? 'vt' : ''].join(' '),` against `:210` `data-font="{{look.font}}" ...`

- Simpler structure, as an instruction to Claude Design: "Make Theme and Layout attributes like the rest: `data-theme="dark"` and `data-layout="grid"`, using the setting ids, and change the selectors (`.th-dark.L-cards` becomes `[data-theme="dark"][data-layout="grid"]`, `.L-rows` becomes `[data-layout="list"]`). Keep `R-pane`, `R-page` and `R-sheet` as the one derived value, renamed `data-reader`, because it depends on the width as well as on Open items as. In the `tokens.css` header list every attribute once with its setting."

- Simpler structure, as an instruction to Claude Design: "Put the two phone rules for Comment style right after the `[data-comments="cards"]` and `[data-comments="rail"]` blocks, so the whole option is in one place, or keep them in section 5 and say so in the Comment style comment. **Bar, hint and phone rules in plain terms**
- Reader bar: starts with the hint (List and Page only), the position text, labelled buttons and the full Back label. After each render it measures; while any part sticks out of the bar, overlaps the part before it or has its own text cut, it drops the next thing: hint, position text, button labels (Mark read and Open become icons, Back to grid becomes Back, Comments becomes "2 of 14"), the comments total ("2"), then Back's word. Under 480px it starts with icons (`PHONE_STEPS`). It starts over when the item, read state, controls, bar width or font change (`Reader.dc.html:244-265`, `:361-378`). When the hint is not in the bar, Page shows it under the item header at 760px or more, List shows it under the search field, and the sheet always pins it to its bottom edge.
- Settings sheet under 760px: backdrop, a 56px header with "Settings" and a 44px Close, a scrolling body, a footer with Reset look. Open items as stays visible, muted, `aria-disabled`, with the note. Close, a tap on the backdrop and Escape return focus to the gear.
- Card images Off: cards drop their picture (`display: none`) and take the text-card look; the reader keeps its picture.
