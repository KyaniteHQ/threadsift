Status: agreed in grill sessions with the owner on 2026-11-03 and 2026-11-04. The visual design of the first screens is finished: a prototype and a design system built in Claude Design (see Design below). The tech stack is chosen in `docs/architecture.md`, which also lists what is built at HEAD (Repository layout). ## Goal

Threadsift is a reading library. A person pastes a link to something they saved (a Reddit post or comment, an X post, a GitHub repo, an article). The app fetches it, keeps only the useful parts, lets an agent tag and summarize it, and shows everything on one page that can be searched and filtered. As Items arrive, the agent also keeps a small wiki of the library: Topic pages, Related Items, an Index and a Log.

The project has two aims:

1. A free, open-source app that anyone can self-host, with a container or a Cloudflare deploy button.
2. Later, the same app as the owner's own hosted product, with its own pricing.

The owner is also a user: they have many saved bookmarks to bring in and read.

## Design

The design is done for every screen in the first spec; the app takes its look from these files, not from new design work. Screens added later follow the Design of new screens decision above.

- **Values:** `design/system/tokens.css` is the one source for every colour, size, spacing, radius, shadow, motion and breakpoint value. Each option of each Look setting is a `data-*` rule on the app's root, and the default option is the plain value.
- **Settings:** `design/system/settings-table.ts` is the one settings table: each setting's id, label, root attribute, kind, group, Look flag, options and default. Every other list (the defaults, the Look settings that Reset look covers, the stored-settings reader, the root attributes) is built from it, and `web/` imports it.
- **Behaviour:** `design/prototype/` shows how each screen behaves: the reader bar drops the key hint, then the position, then button labels until nothing overflows; long comments and code blocks fold; the reading place is restored; the settings panel becomes a bottom sheet with a fixed header and footer under 760px wide.
- **Styles:** the 10 Style blocks live in `design/system/tokens.css`, with a palette for each Theme. Their fonts load from the Instance. The prototype keeps its copy until it imports the system file.
- **Breakpoints:** 480, 760, 1080 and 1440px, with 1, 2, 3, 3 and 4 grid columns from the narrowest band up.
- **Accessibility:** every text and background pair is at least 4.5:1 in every theme with every accent and Style. Every mark, icon and border a person needs to see a control or its state is at least 3:1 in the same combinations (W3C, WCAG 2.2 Non-text Contrast). Dividers, and the edge of a control that shows visible text, may be fainter. Text is never under 12px. Under 480px every target is at least 44px, except a link inside the text of a post or comment, which keeps the size of its sentence (WCAG 2.2 SC 2.5.8, Inline exception; `DESIGN.md` holds the rule). The open row is marked by a bar as well as by colour. Motion has a reduced-motion form.
- **Keyboard:** j and k move through Items, Enter opens, m marks read or unread, / focuses search, the left and right arrows step to the previous or next Item while one is open in Grid, and Escape closes the open Item.

## Ingest flow

```
paste box, Share target, Extension, Import, HTTP API, MCP, Grok Bot
   -> POST /api/items {url} (or {url, content} for a Reddit thread from the Extension and the .json paste, or {url, page} for any other page from the Extension)
   -> classify URL (reddit post | reddit comment | x post | github repo | article | other)
   -> fetch (no LLM), or take the content the caller sent
   -> deterministic clean
   -> agent call: comment filter + Digest (JSON out), unless the caller sent a Digest
   -> store; the Item shows "processing" until done
   -> wiki steps: Topic page, Related Items, Log (see The library wiki)
```

Fetchers:

- **X post:** with a Grok Bot webhook set up, Threadsift hands the link to the owner's bot, which fetches the post, its thread, replies and media through its free X connector and sends them back. Without one, the container build uses the grok CLI, headless: `x_thread_fetch` with the post id, and `x_keyword_search` with `conversation_id:<id> filter:replies` for the replies (tested on 2026-11-03 with grok 1.0.70). The Cloudflare build has no CLI, so there X needs the webhook.
- **Reddit post or comment:** a pasted Reddit link becomes a Link-only Item with its title, author and subreddit from Reddit's oEmbed endpoint. On Save, the Extension makes one signed-in request from the owner's tab, `<thread>/.json?limit=500&raw_json=1`, and posts that JSON. Threadsift reads it with the same parser as the `.json` paste, so one parser owns Reddit JSON. On a 671-comment thread in the owner's browser, the page held 100 comment elements, and the `.json` returned 465 comments plus 199 behind `more` stubs (measured 2026-11-04). After the thread's `.json`, the Extension fetches the replies behind each `more` stub by their own permalink, `/comments/<post>/_/<comment id>.json?limit=500&raw_json=1`, and follows the stubs those answers hold; a stub with no children ("continue this thread") is fetched by its parent's id. One parser reads every answer. `/api/morechildren` answered 403 even to a signed-in session, so the fill uses permalinks. After the thread's own `.json` request, the fill sends at most 100 permalink requests, one start every 500 ms, within a separate 150 s window, and stops at the first HTTP 429, with no retry, and a reply that still fails becomes a Context stub that says it was not saved. On a 677-comment thread the first `.json` gave 464 comments and 34 stubs, and 67 permalink requests, all HTTP 200, brought it to 659 in 51 s (2026-11-05, a throwaway account from a home address). When the `.json` request fails, the Extension falls back to the Reddit extractor of Defuddle (MIT, the extractor behind Obsidian Web Clipper) on the rendered page. A Link-only Reddit Item, such as one shared from a phone or imported from `saved_posts.csv`, is filled when the owner opens that thread in a browser with the Extension, once the owner has turned on "Fill saved Reddit Items" on the Extension's settings page, which asks the browser for reddit.com. The Extension asks Threadsift whether the link is a Link-only Reddit Item and, if so, saves it the same way with `fill`, which never overwrites a saved thread. While such an Item is not processing, the Reader says its thread is not saved yet and how to fill it (`docs/architecture.md`, Extension and Threadsift bot). Not built yet: the Extension's Connect Reddit button. Without the Extension, the owner can send the text of the post's `.json` page from their own browser as `content` of `POST /api/items`; the paste box has no field for it.
  - **Archive fill (self-hosted builds).** A Reddit link that arrives without Extension content (Paste, Import, Share) is filled from Arctic Shift when no Reddit account is connected or the account request fails, `GET https://arctic-shift.photon-reddit.com/api/comments/tree?link_id=t3_<id>&limit=9999` and `/api/posts/ids?ids=<id>` for the post. It is on by default, and a setting turns it off. On the 671-comment thread it returned 661 comments with no `more` stubs in 1.4 s, with no key, from a home address and from a Worker (2026-11-04). Comments that Arctic marks as deleted later (`_meta.was_deleted_later`, 24 of the 661) are dropped, and `[deleted]` and `[removed]` placeholders are treated as the Comment filter treats them. The oEmbed title wins when Arctic's title differs, and the Item names the archive and its date as its source. On a rate limit, a timeout or an outage the Item stays Link-only, with one retry after `X-RateLimit-Reset`, at most 10 s: a reset longer than 10 s, or a second 429, leaves it Link-only without waiting. The fill runs once, when the link is pasted and the Item holds no thread; a later Paste of the same link does not replace a saved thread. The Settings page has one on/off row for it. Extension content replaces an archive fill on the next Save.
  - **The owner's Reddit account (self-hosted builds).** An optional setting connects the owner's own Reddit account. When connected, it is the first server source for a Reddit link without Extension content, before Arctic Shift: it fetches the thread's `.json` and the replies behind its `more` stubs the same way the Extension does, so a thread is complete and current. The requests carry the account's `reddit_session` cookie. In the container they use the platform `fetch`, which got HTTP 200 from a home and a datacenter address (2026-11-04). On Cloudflare, the Workers `fetch` got 403 for the thread's `.json` even with the cookie, while a raw TLS socket from the same Worker got HTTP 200 with 464 comments in 3 of 3 runs (2026-11-05), so the Worker sends these requests over a socket. The setting shows when the session stops working and asks the owner to connect again.
  - **Share links.** `redd.it/<id>` becomes `/r/all/comments/<id>/` without a request. A `reddit.com/r/<community>/s/<code>` link needs one redirect, which Reddit answers without a login (checked 2026-11-08, `docs/architecture.md`, Fetchers): the server follows that one redirect, with no `.json` and no page fetch, and the Item is the post or comment it leads to, with the share link kept as an alias. A redirect that does not end on a post or comment, such as one for a removed link, leaves a Link-only Item under the share link, and the Extension saves the thread at its canonical URL.
  - **Fetcher plug-ins (container only).** A self-hoster adds their own fetcher, at their own risk, as an ES module named in `THREADSIFT_FETCHERS`, which the container loads at start. The Cloudflare build loads none. A Paste of a link the plug-in claims is read by the plug-in before the built-in route, and a page the Extension sent wins over it. A plug-in returns page text only: no comments and no videos. It is never asked about an X or GitHub link, a Reddit link that is not a post or comment, or a Reddit post or comment whose thread is saved. A plug-in that fails, answers an invalid page or answers a page over 1,000,000 bytes ends the fetch `unreadable`, and one that does not answer within the fetch's 2 minutes ends it `timeout`. A plug-in runs inside the app with the Instance's environment and files and its own network access, with no sandbox. `docs/architecture.md`, Fetchers, Plug-ins, holds the contract, the variable's format and the limits.
- **GitHub repo:** the GitHub REST API, anonymous or with the owner's optional token. It gives the description, topics, stars, primary language, last push, license and README. The list row shows the stars, and the Reader shows the rest in a block above the README. The README is kept only when its file name ends in `.md` or `.markdown`; any other format gives no text. A deep link such as an issue address reads its repository. A repository with no README is `ready` with its metadata and no text. A repository answer that is not 2xx (not found, unavailable for legal reasons, private) is no failure: the fetch writes nothing, the Item is `ready` with what it already held (a Link-only Item when it is new), and pasting the link again fetches it again.
  - **Token.** Settings holds the token, sealed on the Instance, with a link that opens GitHub's new fine-grained token page already filled in (a 366-day expiry and no permission, because public repositories need none), a Verify button and a Remove button. The token goes only to `api.github.com`. A token GitHub rejects with 401, or that the Instance cannot open, ends the fetch with a note that tells the owner to replace or remove it in Settings; the Item keeps what it saved before.
  - **Rate limit.** When GitHub answers that a limit is reached, the Item shows that it is waiting and when it retries. The retry time is the later of the reset time and the `Retry-After` wait that GitHub sends, cut to one hour from now, and until then the Instance sends no GitHub request for any GitHub link. A limited fetch is tried 3 times. After the third the Item fails with `rate-limited` and keeps its saved content.
- **Article:** readable text extraction (Defuddle, Readability-style), or the page the Extension sent. A page is an Article when it is HTML and reads as 100 words or more; any other page is Other. The page reader takes HTML up to 5 MiB on the container and 900 KiB on Cloudflare, and a longer page is Other with no post text. The Reader shows a long post text whole (`docs/architecture.md`, Files, holds where it is stored).
- **Other (YouTube and so on):** a Link-only Item with its title.
- **One hop:** when a Reddit post links to an article or a GitHub repository, the Digest also reads that page's text, so the Summary says what the post was about. The link is the post's target, otherwise the first link in the post text. The page is fetched when the Digest runs, used for that Digest only and not saved, so the Reader shows no linked text. A page that cannot be read leaves the Digest to the post and its comments.
- **Media:** an Article's images are downloaded and stored with the Item: the first 20, each up to 2 MiB, and only JPEG, PNG, GIF, WebP and AVIF whose bytes match their declared type. An SVG, a failed or larger image, one past the 20th and an image whose address is on reddit.com, redd.it, x.com or twitter.com stay links to their source. A Reddit page the Extension sent stores its pictures the same way. Videos are kept as links in the text, the first 20 of them are also recorded as video entries, and a YouTube or Vimeo embed becomes a link to its watch page. The Reader draws a stored picture of the open Item; every other image is a link. The List row and the Grid card show the first stored picture while Card images is On.
- **Duplicates:** each Item has one identity, its normalized URL, and pasting a known URL again refreshes that Item. A link loses its fragment, credentials, `www.` and tracking parameters (`utm_*`, `fbclid`, `gclid` and others), and keeps its scheme and the case of its path, so `http` and `https` make two Items. Three Sources have their own rule: an X post is its status id, so x.com and twitter.com, any handle and a media suffix give one Item, while a reply or a quote is another Item; a GitHub repository-root link ignores case and a `.git` suffix, and a deep link is its own Item; a Reddit post or comment id is lower-cased, and a comment is not its post. A short link (`t.co`, `bit.ly`, `buff.ly`, `tinyurl.com`, `ow.ly`, `lnkd.in`, `dlvr.it`, `is.gd`) and a Reddit share link are no identity. The Paste follows a short link's redirects (at most 20) or a Reddit share link's one redirect, the Item is the page it leads to, and the short link is kept as an alias, so pasting it again or pressing Try again refreshes that Item at its saved address even if the short link now points elsewhere or has died. A short link that cannot be resolved is saved under the short link with the failure as its fetch result: a timeout or network error on a new Item ends `failed`, and any other failure (an HTTP error, a redirect that leads nowhere, more than 20 redirects) leaves a `ready` Link-only Item. The next Paste resolves it again.

Why Reddit works this way, checked on 2026-11-04: Reddit blocks anonymous `.json` (HTTP 403 since May 2026), stopped taking new API access requests on 2026-10-31, and its app-registration page says "Remaining public API access will end in March 2027". Its User Agreement forbids scraping without written consent, and its Developer Terms forbid paid use of Reddit data without an agreement. A tab the owner opened by hand sends no server traffic to Reddit, and the archive fill sends none either; only a connected account makes the owner's own server request threads from reddit.com, with the owner's own session. Readeck's add-on works the same way and still works, while tools that fetch Reddit from a server (Linkwarden, Karakeep) are blocked.

## Comment filter

1. The script drops deleted or removed comments, bot accounts (AutoModerator and similar) and short replies with no content.
2. The agent keeps a remaining comment only when it adds a fact, a fix, a working link or command, first-hand experience, or a real counterargument. It drops jokes, agreement and repeats.
3. When a kept reply sits under a dropped parent, the parent stays as a one-line Context stub so the tree still reads correctly.
4. X replies follow the same rules.

The agent makes step 2 in the same call that writes the Digest, over the eligible comments that fit the Digest's input budget (`docs/architecture.md`, AI tasks and Providers, Measured Digest input budget). A comment that does not fit is not Kept, and as a parent it shows as the same stub as a comment the agent dropped. The app drops any id the agent returns that it was not shown. A caller-sent Digest names its own Kept comments, and the agent makes no choice for it.

## Agent output per Item

The agent returns one JSON record, the Digest, stored apart from the fetched content so it can be regenerated without fetching the Item's own link again (a Reddit post's linked page is read again for the Digest):

- a clean title
- one Topic from a Topic list that the agent keeps and grows itself
- up to 3 Tags; before creating a Tag, the agent checks the existing ones, so near-duplicates do not appear
- a 2-line Summary covering the post and what the Kept comments concluded
- Key points
- the ids of the Kept comments

Topic and Tag identity uses `catalogKey` in `src/core/catalog.ts`: NFKC normalization, Unicode full case folding (Unicode 18.0.0), removal of a combining dot above that directly follows an `i`, NFC, trimming and collapsed whitespace. Case, width, composition and spacing do not make a new Topic or Tag: `İstanbul`, `Istanbul` and `istanbul` are one, and so are `Straße` and `STRASSE`, while `café` and `cafe`, `ş` and `s`, `ö` and `o`, and the dotless `ı` and `i` stay apart. The first spelling stays visible. This normalized key is the app's only duplicate check; semantic near-duplicates such as "ML" and "Machine learning" are the model's job from the supplied lists, and later the Proposals' job.

The list uses the stored Digest's clean title and Topic and keeps the fetched title separately. Summary, Key points and Tags wait for the Reader. The last stored Digest stays visible during refresh or regeneration. A failed run shows "No Digest" only when there is no stored Digest; a kept Digest shows "Digest not updated", and both failure states offer Try again, in the list row and in the Reader beside the note. A failed Item's failure note in the Reader carries it too. That action queues a Digest over stored text without a new fetch, and does nothing while a Digest is already open or the Item is failed. An Item with no Digest source (no post text, no eligible comments and, for a Reddit post, no link to a page for the Digest to read) has nothing to queue a Digest over, so its Try again pastes the link again, because only a new fetch can bring text back. A failed Item keeps the paste retry action. The owner session and agent tokens may call it.

A failed fetch keeps the Item `failed` while a remaining Digest closes under it. Otherwise an Item stays `processing` while either job is open, and the batch that closes the last job makes it `ready` with no failure reason. A fetch that replaces the Item's content increments its content generation in the same batch, with or without post text, and opens its Digest there when it has a Digest source: post text, an eligible comment or, for a Reddit post with no caller-sent Digest pending, a link to a page for the Digest to read. A Paste alone does not increment it. Items with no Digest source settle without a Digest job, and a caller-sent Digest they hold is dropped, because there is no text for it to publish over. With a source, the fetch opens a Digest when a Provider is saved or a caller-sent Digest is pending; it decides this in its publishing batch. When a refresh replaces the content without opening a Digest job, because no Provider is saved or the new content has no Digest source, a retained older Digest gets the failure marker and offers Try again.

A Digest waits for an open fetch before calling the Provider. It publishes only at the generation it read. A stale result is discarded, its AI task fails, and the lease-held job returns to the queue on fresh inputs with the same attempt count. Each job run makes at most one model call.

Wrong keys, missing models, refused addresses, missing configuration or sealing secrets, and Provider HTTP 400 or 422 answers give up immediately. Network failures, timeouts, a busy Provider, and a successful HTTP answer whose output fails the Digest schema retry with the job runner's delays. A failed Digest leaves fetched content readable.

`POST /api/items` accepts a caller-sent Digest from the owner session or an agent token. Invalid Digests return 400 before storage. The last Paste sets or clears the pending Digest. A fetch with no text drops it and keeps any stored Digest; a fetch with text lets it publish by normalized key, without a catalog guard or a Provider call. Its AI task starts before publication with executor `caller`, with no Provider or model; a failed publication leaves a failed task record. Try again always uses the configured Provider.

## The library page and the Reader

- **Paste card.** A Paste shows a card under the paste box that says what is happening: reading the link, added, already saved and refreshed, or a failure note with Try again. The Added and refreshed cards have Open and Dismiss. The Added, refreshed and failure cards close themselves after 6 seconds, held while the pointer or focus is inside. Try again on a row uses the same card: for an Item with no stored text it pastes the link again, and for one with a failed Digest it queues a Digest over the stored text.
- **Search and filters.** The list head says how many Items match. When none do, one button, Clear search and filters, resets both. The API behind the counts is under Interfaces.
- **Read state.** An Item is unread until the owner marks it read, from the Reader bar, the dot on its row or the `m` key. The agent, a refresh and a Digest never change it. In the List Layout at 760px wide and over, the first load opens the first unread Item once and leaves it unread; an Item named in the address wins, and under 760px nothing opens.
- **What the Reader shows,** top to bottom: the header (Source, place, author, posted and saved times, title); the Topic, Tags, Summary and Key points; for a GitHub repository, its block of description, stars, language, license, last push and topics; the post text (the README for a repository); the Kept comments; the Highlights list; and the Note box. Markdown shows without raw HTML, and only `http`, `https`, `mailto` and in-page links work. When a later read of the Item fails, the Reader keeps the body it has, says it may be out of date and offers Try again. The bar holds the Comments button, Mark read or unread, Open on the Item's Source and Delete, and it drops the key hint and then the button labels until it fits.
- **Kept comments.** Replies nest under their parent, drawn in the Comment style the owner chose, and the Item author's comments carry an OP badge. A comment longer than 8 lines folds, and keyboard focus that lands inside a fold opens it. A Context stub marks a dropped parent, and a stub that says "Further replies were not saved." marks replies behind a `more` stub. The Comments button jumps to the section and shortens to "N of M" and then to the count as the bar narrows. A row reads "Kept N of M" for an Item with comments, and "Saved comment" for a saved Reddit comment.
- **Highlights.** The owner selects one passage inside the post text or inside one Kept comment, and a popover offers Keep. A selection across two bodies, or one that touches a control or a Context stub, offers nothing. A kept passage is marked in place, in List, Grid Page, Grid Sheet and on a phone. Pressing a mark offers Remove, and Escape closes the popover without closing the Reader. The Highlights list at the end of the Reader holds every Highlight of the Item, and choosing one scrolls to its mark and opens the fold around it; a Highlight whose passage is gone shows its quote with the note "Passage no longer found because the item’s text changed."
- **Note.** The Note box follows the Highlights list. Its rules are in the Highlights and Notes decision.
- **Reading place.** Each browser tab remembers where the owner stopped in each Item and returns there on reopen, as long as the text at that place is still in the Item.
- **Delete.** Delete asks "Delete this item?" with Cancel and Delete item. While the request runs both buttons and Escape do nothing, and after 20 seconds without an answer the dialog reports the failure and offers both again.

## The library wiki

A small version of the LLM wiki idea (https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f): the agent builds the synthesis once, when an Item arrives, and keeps it current, instead of searching raw content at question time. Each Item's Digest is its summary page; the four parts below add the rest.

1. **Topic pages.** Each Topic has a page with a 3 to 5 line overview the agent writes, and the list of its Items with their Summary lines. After each new Digest, one small agent call revises the overview of that Item's Topic from the overview and the new Digest, or leaves it unchanged. The overview names the Items it was built from, so it never stands in for them. The page is reached from the Topic in the Reader and in the filters pane. Its address holds the Topic's catalog key, so `İstanbul` and `istanbul` are one page. A failed overview shows on the page with Try again and the list of Items still shows. With no Provider saved the page shows the Items and no overview. Deleting an Item removes it from the list at once, and the next overview run drops it from the overview. One run makes one agent call over as many uncovered Items as fit its input, so several Digests that arrive close together usually share a call. When more remain, the run starts the next one itself, until every Item is covered.
2. **Related Items.** The Reader shows up to 5 Related Items, each with a one-line reason. The app finds candidates with the full-text search, and the agent picks the real ones. Related Items are links between Items, not prose inside a page.
3. **Index and Log.** The Index lists every Topic with its Item count and its overview line. It is reached from a link in the settings panel beside Highlights and lives at `/topics`. A row appears once for each Topic, by the name it was first spelled, ascending by its catalog key, 50 to a page with Load more; a row opens the Topic page. The count is the number of Items in the Topic, and a Topic whose Items were all deleted stays in the list with 0. The overview line is the first line of the stored overview with its `[12]`-style citation marks removed, because the Topic page shows no mark as raw text; a Topic with no overview has no line, and a failed overview still shows the text it has stored. The Log lists every agent action, newest first, in the form `[2026-11-04] ingest | <title> | topic: X | tags: a, b`, including created Topics, renamed Tags and regenerated Digests. The app builds both from stored records, with no agent call.
4. **Proposals.** Once a week, the Proposals page lists changes the agent suggests and never makes on its own: merge two Tags, merge two Topics, two Items in a Topic that disagree (with both Summary lines), an Item no overview mentions, a Highlight no longer found. Plain checks find the duplicates and orphans; the agent runs only on the Topics those checks touch. The owner accepts or rejects each one, and the app applies the accepted ones. An accepted correction is kept as a Pin, so the next regeneration cannot undo it.

The owner's Highlights and Notes are never regenerated or rewritten by the agent.

The rules above answer the known failures of LLM wikis, from the gist's comments: a wrong merge becoming a permanent error (overviews cite their Items, changes go through Proposals), human corrections lost to regeneration (Pins), and near-duplicate pages from parallel updates (one update at a time per Topic).

## AI providers

The owner picks one Provider in the AI settings, and the screen shows only the fields that Provider needs. "Verify" runs one small real Digest, so a model that cannot return the Digest's JSON fails at setup, not on the 200th Item.

The Settings page offers OpenAI-compatible URL, OpenRouter, Anthropic, OpenAI and xAI, Workers AI on Cloudflare, and on the container Claude Code on this server and Codex on this server (each takes a model that may be left empty and no key; the Grok CLI is not offered, because `docs/architecture.md`, CLI executor, Grok CLI, records that 1.0.77 gives no proof of its tools before a model request), reached through the gear panel’s Instance settings link. Anthropic, OpenAI and xAI each take a model and an API key; their URLs are fixed. Save keeps the API key sealed on the Instance; the screen only reports whether a key is set. Verify uses the saved settings and shows a Digest or a refusal with a recovery action. It adds no Item, Topic or Tag. Fetched Items with post text now get automatic Digests when the saved Provider loads. The Topic and Tag lists and caller-sent Digests are built. Saving a Provider opens Digest jobs for older Items with post text, no stored Digest, no failure marker and no open Digest job. Saving again does not reopen failed Digests; Try again owns that retry. This spends one model call per eligible Item, with 4 jobs at a time in the container and up to 100 per minute on Cloudflare. OpenRouter ran a real Verify on the container on 2026-11-07 with a free model. Anthropic, OpenAI and xAI have no successful live run until the owner supplies a key; only their refusal of a wrong key was run against the vendors.

- **CLIs:** the app never reads or stores a CLI's login; the owner signs in with the CLI's own command, or starts the container with a token from `claude setup-token`, which the app passes unchanged to the CLI. Codex has no token variable: the owner runs `codex login --device-auth` in the container, and the login stays in the `/data/codex` folder of the volume. The AI settings show the sign-in command when the CLI is signed out, and Save and Verify stay off until it is signed in. The CLI runs with its tools turned off in an empty folder and a minimal environment, because every Digest call reads other people's posts (for Codex the app removes the tools from a copy of the model catalog, since Codex has no switch for that); `docs/architecture.md`, AI tasks and Providers, holds the flags and limits. At most 2 CLI tasks run at once on an Instance, Verify and Digests together, across both CLIs, because a plan is one person's quota.
- **OpenRouter Connect:** the Connect button sends the owner to OpenRouter to approve a key (OpenRouter's PKCE flow) and saves the returned key sealed, like a typed key. It needs the Instance's public address (`THREADSIFT_PUBLIC_ORIGIN`: an `https` origin, or `http` on localhost); without it the button gives way to a note. A Save the owner makes while on OpenRouter's page wins, and the Connect result is dropped. OpenRouter turns a new key on some seconds after it makes it (up to 17.2 s in 16 runs on 2026-11-08), so Connect checks once a second for up to 45 s whether the key works before it saves; the last check may take its own 8 s timeout. When the key is still not active, it saves the key, says so, and opens no Digests for older Items until the owner saves again. An attempt expires after 10 minutes.
- **Plans:** Anthropic allows "an end user… signing in to the unmodified Claude Code binary with their own Claude subscription" and forbids a third party from offering "Claude.ai login" or routing plan credentials for its users (`code.claude.com/docs/en/legal-and-compliance`, read on 2026-11-04). So the hosted product never offers a Claude plan login. Plan limits are small for an Import, so the Import screen suggests an API key when a plan Provider is picked.
- **Default model:** during the build, a 20-Item comparison of the Providers picks the recommended default by Tag quality, Digest quality and run time.

## Grok Bot

```
A. The owner drops a link in a Grok Bot chat
   owner -> Grok Bot -> POST /api/items (MCP or token) -> Threadsift

B. Scheduled X bookmark sync
   Grok Bot (every few hours) -> reads new X bookmarks -> POST each to Threadsift

C. Intake webhook
   owner pastes an X link into Threadsift
   Threadsift -> POST the link to the routine's webhook URL and key -> Grok Bot wakes
   Grok Bot -> fetches post, thread, replies (X connector) and writes the Digest
   Grok Bot -> POST /api/items with the content and the Digest -> Threadsift
```

- **Setup:** the owner connects Threadsift to Grok Bot once, with Threadsift's URL and a token. For C, they paste the webhook routine's URL and key into Threadsift's Grok Bot settings, which has a Test button that sends a harmless ping. The key stays on the server.
- **The Threadsift bot:** a public Grok Bot template with skills that save links dropped in chat, search the library, run the X bookmark sync and answer Threadsift's webhook. Its setup skill walks the user through adding their Threadsift URL and token, because a template cannot carry a custom MCP server.
- **What the API needs for it:** `POST /api/items` is idempotent by URL, accepts content and a Digest the caller already wrote, and returns the Item's URL so the bot can link it in chat; `POST /api/items/batch` takes many links with a cursor (the last bookmark id) that the Instance keeps, so a routine sends only what is new (Interfaces).
- **AI tasks:** when Grok Bot is the Provider, Threadsift also sends it each wiki task (a Topic overview, a Related Items pick, the weekly Proposals) through the same webhook, and the bot posts the result back; without Grok Bot, every task runs on the Provider the owner picked (decided 2026-11-04, `docs/architecture.md`, AI tasks and Providers).
- **Speed:** an X link through the webhook takes seconds to tens of seconds longer than a direct fetch (Grok Bot's own estimate, not measured), because the bot has to wake and run.
- **Later:** a listing in Grok Bot's plugin catalog, once the way a third party gets listed is known. That listing needs OAuth on the MCP endpoint.

Grok Bot's capabilities above come from asking the owner's Grok Bot on 2026-11-04; it marked each answer as checked or inferred.

## Interfaces

- The paste box, the Extension and agents use the same HTTP API: `POST /api/items {url}` to add, `GET /api/items?q=&topic=&tag=&source=&read=&url=&cursor=` to query (`source` is one of reddit, x, github, article and other; `read` is read or unread; `topic` and `tag` match by name with case and spacing ignored; `cursor` is the `next` of the page before), `DELETE /api/items/:id` to delete, `GET /api/topics/:key` to read a Topic page (the key is the Topic's catalog key, with one more `~` in front when it is only dots or `~` before dots) and `POST /api/topics/:key/overview` to write its overview again. Every call needs the owner's session or an agent token, except the session check, the first-run setup, the sign-in and the password reset. The owner's session alone, never an agent token, calls `/api/settings`, `/api/tokens`, `/api/password`, the sign-out, a Read state change, a Highlight and a Note (`docs/architecture.md`, Access). The `url` filter finds one Item by its normalized URL; the Extension uses it to fill a Link-only Reddit Item. `POST /api/items/batch {links, import?}` saves 1 to 100 links in one call for a routine or an Import. It runs the Paste of `POST /api/items` on each link in order, except that a link the library already holds is not refreshed and answers `known`: an Import adds Items, and refreshing a library would cost one model call per link. `results[i]` answers `links[i]` with `added`, `known` or `refused` (a host that is not globally reachable, which does not stop the other links). An invalid entry answers 400 with its index and saves nothing, and a library being updated answers 503. `import` is `{name, cursor}`: the caller picks the `name` and an opaque `cursor`, such as the last bookmark id. The Instance saves the cursor only after every link has an outcome, so a call that dies half way leaves the old cursor and the repeat answers `known` for the links already saved. `GET /api/imports/{name}` reads it back. An agent token calls both. The Import screen is one caller: it names the `import` after its list and sends the number of links done as the `cursor`, in calls of up to 100 links (`docs/architecture.md`, The import cursor).
- `GET /api/items` answers one page of the matching Items, newest saved first, at most 50, with `next`, the `cursor` that reads the following page (null on the last page; a caller that needs every Item sends `next` back, with the same filters, until it is null). With no `cursor` it also answers the counts the filter pane shows: the library total and unread count, and a count for each Source, Read state, Topic and Tag, over the whole library and not the page. A page read from a `cursor` carries no counts. Each group's counts apply the search and the other groups' filters but not its own group, so a count equals what choosing that value leaves. Each Item carries `commentsKept` and `commentsTotal` for its row: both are null until a Digest has published the Item's Reddit thread, and the total is the larger of the post's reported comment count and the comments received. `fillable` is true for a Reddit post or comment Item that holds no saved thread; the Extension reads it with `url` to fill a Link-only Item. Search splits `q` into runs of letters and digits, each run is a prefix match, and every run must match; a `q` over 200 characters, an unknown `source` or `read`, or a malformed `cursor` answers 400.
- `POST /api/items` takes `url` and, optionally, a `digest`, `fill`, and at most one of `content` and `page`. It answers `{item, url}` with 201 for a new Item and 200 for a known one it refreshed. `content` is the `.json` of a Reddit thread, one text or 1 to 101 (the thread first, then the answers behind its `more` stubs), each up to 4 MiB. `fill: true`, sent with `content` only (400 otherwise), saves the thread only into the Item with that link while it holds no saved thread. `page` is `{markdown, title, author?, published?, videos?}` read in the caller's own tab, up to 1,000,000 bytes once serialized, and it takes no X or GitHub link and no Reddit link that is not a post or comment (400, with `code: unsupported-link`). A `content` thread whose post text or any comment body is over 1,000,000 bytes is refused with 400. Answers: 413 over a size limit (the request body holds 8 MiB here and 64 KiB on every other route), 409 when a `page` meets a Reddit thread already saved or a `fill` finds no Item waiting for its thread, and 503 while a new release is rewriting stored Items. A link whose host is not globally reachable answers 400.
- `GET /api/items/:id/status` answers the Item as the list shows it, with no post text, for polling a `processing` Item. `POST /api/items/:id/digest` queues a Digest over the stored text, never a fetch of the Item's own link (a Reddit post's linked page is read again for the Digest), and does nothing while a Digest is open or the Item is failed.
- `GET /api/items/:id` answers the Item with its post text, a `digest` of Summary, Key points and Tags (null while the Item has none), `repository` for a GitHub repository, `images` (each stored picture's address and size), `comments` (the Kept comment tree and its counts), `highlights` and `note`. `GET /api/files/items/:id/:name` serves a stored image of that Item and nothing else, to the owner's session or an agent token, and a file that no stored image names answers 404. `PUT /api/items/:id/read-state` takes `{readState: "read" | "unread"}`, answers the Item as the list shows it and is closed to agent tokens (403), because the owner alone sets Read state; an unknown id answers 404 and any other value 400.
- `POST /api/items/:id/highlights` keeps a Highlight from the target (the post text, or a comment's id), the revision of the text the owner read and the selection with its surrounding words; it answers 201, 200 when the same passage is already kept, 400 when the selection is not in that text and 409 when the text changed since. `DELETE /api/items/:id/highlights/:highlightId` removes one. `PUT /api/items/:id/note` takes `{body, revision}` and answers 409 with the stored Note when its revision moved; an empty body clears the Note. All three answer 403 to an agent token. `GET /api/highlights?q=&source=&topic=&tag=&cursor=` answers one page of the Highlights page (see Highlights page above) and is open to agent tokens.
- `GET /api/topics?cursor=` answers one page of the Index: `{ topics, total, next }`, where each topic has `key`, `name`, `itemCount` and `overviewLine` (a string or null). The topics come ascending by key, at most 50, and `next` is the `key` to send back as `cursor` (null on the last page). It takes the owner's session or an agent token, and a `cursor` longer than the longest catalog key a Topic name can make (4,320 characters) answers 400. The MCP endpoint has no tool for it.
- The MCP endpoint, `/mcp`, offers the tools `search`, `read` and `add` for agents that speak MCP (see Agent access above). They take the filters, the Item id and the link with an optional Digest of the HTTP calls above and answer the same data. It takes an agent token and no owner session (`docs/architecture.md`, Access, MCP), so it cannot write a Highlight, a Note or a Read state, and `add` sends no page or thread content.
- The Web Share Target is a form `POST /share` that the app handles on the server. A trusted share calls the same core save as `POST /api/items`; the owner's session cookie, the browser's `Sec-Fetch-Site: same-origin` and an `Origin` that names the Instance are all required, and an agent token never authorizes it (see `docs/architecture.md`, Web app).
- The Export is one download of the whole library (see Export above). Not built yet.
