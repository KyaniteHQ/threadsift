# Testing

The testing policy for this repository; it overrides broader testing instructions. Read it before writing, changing or deleting a test. `docs/architecture.md` (Testing) says how the suites are built.

- Tests run the real code on a real database and real runtimes. The app has no mocks, stubs, fakes, replayed recordings or test-only seams. A vendor's own local runtime (`wrangler dev` with local D1, R2 and Queues, Podman, Chromium) counts as real.
- Core tests in `test/*.test.ts` start the real app in process on a temp database with the real `migrations/` and call it through `app.request`. They reach no network and no Provider, and each file states the requirement it proves. Run them with `pnpm test`; the `check` job and the pre-push hook run them too. A parser that takes literal input, such as `readArticle` and `catalogKey` in `test/parsers.test.ts`, is also tested by calling it directly, because its input and output are values and no request reaches it; any rule that a request can meet, such as the refusal of a host, is tested through `POST /api/items`.
- The gate without the browser smoke is `devenv tasks run ci:gate`, and the `check` job runs the same command. `devenv test` is not the gate, because it starts the dev `processes`.
- One browser smoke spec, `smoke/smoke.spec.ts`, runs on both install targets on every pull request. Run it with `devenv tasks run smoke:worker` and `devenv tasks run smoke:container`. Each checkout builds and runs its own image, `localhost/threadsift:smoke-<slot>`, on its own port, so two worktrees can run it at once (`docs/architecture.md`, Smoke).
- The live check, `smoke/live.spec.ts`, reaches the internet daily on `main` and blocks neither a pull request nor the deploy. On the container it also calls a real model, the owner's Claude subscription through the Provider "Claude Code on this server". The Worker run calls no model: its Pastes carry a caller-sent Digest. Run them with `devenv tasks run live:worker` and `devenv tasks run live:container`. `live:container` needs `CLAUDE_CODE_OAUTH_TOKEN` from `claude setup-token` and fails at once without it; it installs Claude Code in the container, so it needs the network.
- Checks against a deployed copy run on the owner's machine, never in CI. Run `tools/check-deployment.ts` as [Check an Instance](deployment-check.md) describes; Provider mode and caller-supplied publication mode prove different contracts. Preview provisioning creates the demo owner, the demo Items and, when the database has a `proposals` table, the demo Proposals (Tag pairs, Topic pairs when the database has the column `from_topic_id`, lost-Highlight rows on demo Highlights when it has the column `highlight_id`, and overview-gap rows on three demo Topics when it has the column `topic_id`; one `wrangler d1 execute` insert), and saves no Provider; it runs no deployed check suite.
- Only the `deploy` job in `.github/workflows/gate.yml` targets `--env live`. The separate PR preview workflow runs remote commands only against its PR manifest (`docs/pr-previews.md`). A machine signed in to Wrangler reaches the live account, and `CI=true` skips Wrangler's confirmation prompt, so a local check uses `--local`.
- A change is proven by running the real program the way its caller does, and the command and its output are kept as the artifact. A bug fix is proven by one reproduction that fails before the fix and passes after it.
- A flaky run is rerun, and its cause is fixed in the test, not hidden behind a retry or a sleep.
