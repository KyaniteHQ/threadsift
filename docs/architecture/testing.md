# Testing

`docs/testing.md` is the project's testing policy: real code, a real database and real runtimes, with no mocks, fakes or recordings.

- **Core tests.** `pnpm test` defaults to one Node process per available CPU, capped at the number of core test files. Files in a shard share a process so they pay the app import cost once. On the owner's 16-CPU workstation with Node 26.13.1, the command took 63.6 s on 2026-11-21. The core tests reach no working Provider and no external host but the two that `docs/testing.md` names, because the save route takes the page and the Digest from the caller and an X link stores a Link-only Item without a fetch. `test/fetchers/` holds real fetcher plug-in modules that the tests load through the production loader. `test/fetcher-deadline.test.ts` aborts `pluginPage` after all three fixture fetches start, because the job's own deadline is 120 s. The Reddit-with-a-thread rule is not in the core tests, because the built-in route it falls back to requests reddit.com. The cases that reach the fetch handler run through `runJob` and `executeClaimed`: a Reddit job that finds the turn taken, and a job that runs out of attempts. The one-hop scheduling test stores a GitHub cooldown row, so its hop ends as `waiting` before any request; the cases that reach the network (a refused address, a timeout, a 404) run only in the real runs.
- **Smoke.** `smoke/smoke.spec.ts` drives Chromium through the app's main flows on both targets; the `test.step` calls in it and in the files it imports name every step. `smoke/document-checks.ts` also fails the run when the document at `/` or `/log` differs from a header of `DOCUMENT_HEADERS`, or when a page reports a `securitypolicyviolation` event. Each watched context ends with a script that the policy blocks on purpose and fails when that violation does not arrive, which shows its collector works and that every earlier report has arrived. `playwright.config.ts` starts the target named in `THREADSIFT_TARGET`: `wrangler dev --local` on `.wrangler/smoke`, or `podman run` of the image that `container:build` builds. Run it with `devenv tasks run smoke:worker` and `devenv tasks run smoke:container`. Every smoke and live task (`devenv.nix`, `checkoutEnv`) derives its image tag and port from the checkout's path, so two worktrees build, run and serve their own image on their own port at once. Two paths can share a port with a chance of 1 in 10000 (arithmetic); the second run then fails to start. `container:build` labels the image `io.threadsift.smoke=true` and prunes labelled images that no tag points to and no container uses, so a checkout cannot remove another checkout's image even when the two tags share an image ID. A removed worktree leaves its tagged image behind. List the tagged images with `podman images --filter reference='localhost/threadsift:smoke-*'` and remove the ones you no longer need with `podman rmi <image>`.
- **Live check.** `smoke/live.spec.ts` is the `live` Playwright project, which reaches the internet and, on the container, a real model; see Live check in `ci-releases-and-rollback.md`. Run it with `devenv tasks run live:worker` and `devenv tasks run live:container`, with, to avoid GitHub's anonymous limit, `GITHUB_TOKEN` in the environment (optional locally). `live:container` also needs `CLAUDE_CODE_OAUTH_TOKEN`, and `live:worker` needs no model credential.
- **Not run any more.** The Extension in a real browser as a check of the gate, the Highlights page in a browser, the contrast and layout-shift checks of the earlier design specs (the static `impeccable detect` check still runs, and the smoke spec measures some touch targets against 44px on a phone: the Import and Index links of the settings panel, an Index row, the filter rail's Topic link and the two links of an `ingest` Log entry), the Codex executor, every Provider but Claude Code (which runs on the container only, so no check runs OpenRouter or any other HTTP Provider), and the earlier broad checks against a deployed copy.
