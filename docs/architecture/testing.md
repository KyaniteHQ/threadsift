# Testing

`docs/testing.md` is the project's testing policy: real code, a real database and real runtimes, with no mocks, fakes or recordings.

- **Core tests.** `test/*.test.ts` run with `node --test` (`pnpm test`, 3.3 s on 2026-11-10). `test/instance.ts` starts the app the way the Node target does: `openDatabase` on a temp file with the real `migrations/`, `startNode` with a temp data folder, `createApp`, then `app.request`. They reach no network and no Provider, because the save route takes the page and the Digest from the caller and an X link stores a Link-only Item without a fetch. `test/fetchers/` holds real fetcher plug-in modules that the tests load through the production loader (`Instance.start` passes the raw `THREADSIFT_FETCHERS` text to `startNode`). `test/fetcher-deadline.test.ts` calls `pluginPage` with a short signal, because the job's own deadline is 120 s; the Reddit-with-a-thread rule is not in the core tests, because the built-in route it falls back to requests reddit.com. The one-hop scheduling test stores a GitHub cooldown row in the database, so its hop ends as `waiting` before any request, and the Provider it saves is never called; the cases that reach the network (a refused address, a timeout, a 404) run only in the real runs.
- **Smoke.** `smoke/smoke.spec.ts` drives Chromium through setup, sign-out and sign-in, an X link Paste that survives a reload, an X post with its replies sent through the API with a caller-sent Digest (`readXThread` in `smoke/reader-flows.ts`: the list row's "Kept 2 of 3", the Kept replies with their `@handle` and the OP badge, no archive note), a saved page opened in the Reader, the Reader's Topic link opening the Topic page (a dotted Topic name, reloaded on its address), and the Index (the settings panel's link, a Topic's row with its count, a reload on `/topics`, the row opening the Topic page, and a signed-out visit that gets the sign-in screen), and the Log (`smoke/log-flow.ts`: a Paste with a caller-sent Digest, the settings panel's link, `ingest` above `topic`, a reload on `/log`, the title opening the Item and the Topic name opening its page, a 390 px page with a long title and three Tags that does not scroll sideways, link targets of at least 44 px in width and height on that line and on a line with a one-word title and Topic, a signed-out visit, a delete that removes the `ingest` line and keeps the `topic` line, and a Load more that fails while the browser is offline and works on Try again from the keyboard, with focus landing on the first link of the first new line). `smoke/document-checks.ts` makes the same run fail when the document at `/` or `/log` differs from a header of `DOCUMENT_HEADERS`, or when a page of the signed-in browser context or of a signed-out visit (`visitSignedOut`) reports a `securitypolicyviolation` event. Each watched context ends with a script that the policy blocks on purpose and fails when that violation does not arrive, which shows its collector works and that every earlier report has arrived. `playwright.config.ts` starts the target named in `THREADSIFT_TARGET`: `wrangler dev --local` on `.wrangler/smoke`, which the command empties first, or `podman run` of the image that the `container:build` task builds from the `Containerfile`, under the name in `THREADSIFT_IMAGE`. The container is named `threadsift-smoke-<port>`, writes its log to `.wrangler/smoke-container-<port>/`, and starts with `CONTAINERS_CONF_OVERRIDE` pointing there at a `containers.conf` whose `pasta_options` turn on pasta's debug log, so the capture of a failed run holds that log; on a Podman that does not use pasta the option has no effect and the capture has no pasta log. Run it with `devenv tasks run smoke:worker` and `devenv tasks run smoke:container`. Every smoke and live task (`devenv.nix`, `checkoutEnv`) derives a 12-character `slot` from the SHA-256 of `DEVENV_ROOT`, the checkout's path, and sets `THREADSIFT_IMAGE` to `localhost/threadsift:smoke-<slot>` and `THREADSIFT_SMOKE_PORT` to 20000 plus the slot modulo 10000. Two worktrees therefore build, run and serve their own image on their own port at once. Two paths can share a port with a chance of 1 in 10000 (arithmetic); the second run then fails to start. Outside the tasks, `playwright.config.ts` falls back to port 8799 and needs `THREADSIFT_IMAGE` set. `container:build` labels the image `io.threadsift.smoke=true` and, after the build, runs `podman image prune --force --filter label=io.threadsift.smoke=true`, which removes the labelled images that no tag points to and no container uses, and never an image that carries a tag, so a checkout cannot remove another checkout's image even when the two tags share an image ID. An image that a container still used at that build stays untagged until a later build runs the same prune. A removed worktree leaves its tagged image behind. List the tagged images with `podman images --filter reference='localhost/threadsift:smoke-*'` and remove the ones you no longer need with `podman rmi <image>`.
- **Live check.** `smoke/live.spec.ts` is the `live` Playwright project, which reaches the internet and, on the container, a real model; see Live check in `ci-releases-and-rollback.md`. Run it with `devenv tasks run live:worker` and `devenv tasks run live:container`, with, to avoid GitHub's anonymous limit, `GITHUB_TOKEN` in the environment (optional locally). `live:container` also needs `CLAUDE_CODE_OAUTH_TOKEN`, and `live:worker` needs no model credential.
- **Not run any more.** The Extension in a real browser, the Highlights page in a browser (its list, search, filters, keys, empty and failed states, Load more, the arrival in the Reader and every Theme at 1440 and 390 px), the contrast, touch-target and layout-shift checks of the earlier design specs (the static `impeccable detect` check still runs), the Codex executor, every Provider but Claude Code (which runs on the container only, so no check runs OpenRouter or any other HTTP Provider), migrations over a seeded older database, and the earlier broad checks against a deployed copy. The earlier end-to-end suite ran them. `tools/check-deployment.ts` checks sign-in, a real Paste through the Queue and Digest publication on the owner's machine; [Check an Instance](../deployment-check.md) distinguishes Provider and caller-supplied proof.
