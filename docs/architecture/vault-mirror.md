# Vault mirror

`src/core/vault-mirror.ts` drains the queue through the same GitHub Git Data API writer on both install targets. `src/http/vault-routes.ts` and `web/src/ObsidianPage.tsx` own the owner-only settings routes and screen.

- **Identity.** Item notes use `Threadsift/items/<Item id>/note-<Item id>.md`. The Item id survives refresh, title, Topic and Tag changes, Export and Restore. A nonempty title becomes an `aliases` entry. `itemNote` in `src/core/item-note.ts` is shared with the Export, which keeps its title-based file name. Images and stored post text keep their existing file keys under `Threadsift/`.
- **Queue.** `queueVaultItems` joins the Paste's batch, including thread publication and failed short-link resolution. `mirror_notes` holds unique `(kind, subject_id)` subjects with advancing sequences; its first supported kind is `item`. It has no Item foreign key, so a deletion survives Restore undo. The Export excludes the queue, the written-path inventory `mirror_files`, the uploaded-blob cache `mirror_blobs` and the sealed `vault_settings`.
- **One writer.** The generation and sealed credential identify the singleton lease. `vaultCurrent` checks that lease, the queued sequences and the canonical Restore hold immediately before the branch update. Acknowledgements remove only sequences at or below those read. An answer lost after GitHub committed leaves the queue for another attempt. Ref updates never force the branch.
- **Bounds.** `VAULT_NOTE_LIMIT` and `VAULT_DEADLINE_MS` are chosen bounds. `detailReads` issues 11 SELECT statements per Item in one batch, so 20 notes use 220 Reader SELECT statements, in 20 D1 batch calls. D1 counts a batch as one query against its per-invocation limit of 1,000 on Paid and 50 on Free ([D1 limits](https://developers.cloudflare.com/d1/platform/limits/)); this arithmetic is not a measured production bound and excludes the writer's other queries. A batch stops before 500 paths or 8 MiB of text; an Item with binary files gets its own batch. A single Item may exceed the text budget, as in the Export.
- **Files and retry.** `vault-blob.ts` reads, encodes and uploads one binary at a time and checkpoints each content digest's blob SHA for later attempts. The deadline starts at claim time. Missing or changed stored files park only that subject for a minute and log the reason; healthy subjects can drain. `vault-tree.ts` reads only needed nonrecursive subtrees, so an unrelated large vault does not require a complete recursive tree. An unchanged tree creates no commit. Requests are serial, with at least one second between mutations ([GitHub REST best practices](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api)). Rate limits persist GitHub's retry time for the same sealed credential even after lease expiry; other failures wait a minute. The tick runs sweep and mirror as separate best-effort tasks.
- **Restore.** The canonical `HOLDS_LIBRARY` predicate pauses the writer while the newest Restore holds the library. Starting a Restore invalidates the lease. Save and a completed or cancelled Restore reconcile the repository's managed Item paths with the current library, including paths written by another Instance. Cancelling an upload that never changed the library does not requeue it. No mirror table is restored from a zip.
- **Settings.** `vault-settings.ts` seals tokens through the Instance's `Sealer`. Verify reads a candidate branch without saving or writing files; it does not prove Contents write permission or permission to update a protected branch. A missing sealing key prevents Save. Disconnect leaves repository files in place.

## Design, not built

- **Folder mode, container only.** Write the same files into a mounted vault folder.
- **Other content changes.** Queue the affected note subjects in the same batch as a deleted Item, a new Digest, a Read state change, a Highlight or Note, a Topic page, a Related Item, a Log entry, an Index change, or an accepted Proposal. A Proposal that renames or merges Topics or Tags rewrites every affected note. The current slice queues Pastes and reconciliation only.
- **Topic paths and links.** A Topic page note keeps its first path through a rename. An accepted merge deletes the merged-away Topic's note and rewrites wikilinks to the survivor. Related Items become wikilinks. Topic page notes, the Index and the Log extend the existing subject queue and writer.
- **Oversized files.** Leave a file above GitHub's 100 MiB limit out of the vault and add a line to the Log ([GitHub large files](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)).
