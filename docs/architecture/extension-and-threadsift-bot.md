# Extension and Threadsift bot


- The Extension is built with WXT for desktop Chrome and Firefox (Manifest V3) and posts to `POST /api/items` with an agent token. It saves one page per click and never crawls.
  - **Reddit.** On Save in a tab on a Reddit post or comment, the background worker asks the tab for `<thread>/.json?limit=500&raw_json=1` through `scripting.executeScript` with a function that calls `fetch`, so the request carries the tab's Reddit session (`extension/lib/reddit-thread.ts`). `hiddenRepliesOf` (`src/core/contract/reddit-tree.ts`) lists the comment ids behind each `more` stub of an answer. The worker requests each id at `/comments/<post>/_/<id>.json?limit=500&raw_json=1`, because `/api/morechildren` answered 403 to the signed-in session (owner's browser, 2026-11-04), and posts every answer in one request: `{url, content: [thread, ...permalink answers]}`. The pace is our choice, not Reddit's: 500 ms between the starts of two requests and 150 s per thread (`REQUEST_SPACING_MS`, `FILL_DEADLINE_MS`), against the 67 permalink requests after the first `.json` request in the measured 677-comment thread (`docs/architecture/decisions-and-evidence.md`, Reddit). The count is Reddit's: it answers `.json` requests with `x-ratelimit-used`, `x-ratelimit-remaining` and `x-ratelimit-reset`, allows 100 requests per window of about 600 s (owner's browser, 2026-11-13; the window length is inferred from the `reset` values) and refuses the 101st with HTTP 429. A `RequestWindow` (`src/core/contract/reddit-http.ts`) counts every request of the fill, the thread's own included, and keeps the last count Reddit reported; an answer without a readable header takes 1 off that count, and the fixed cap `REDDIT_WINDOW_REQUESTS` applies on its own only while no header was read. `mayAsk` stops the fill before the request that would be refused. The fill still stops at the first HTTP 429, which covers another `.json` request that used the window, such as a second thread saved within 10 minutes. Any other failed request is not retried and leaves its stub. No request starts once the 150 s are used, and the timeout of each request (15 s) is cut to the time left, so the fill never runs past the deadline by a request. The thread is saved with what the fill read; when stubs are left (`unfilledStubsOf` in `src/core/contract/reddit-tree.ts`, those with no id to request and those whose permalink answer was empty included), the popup says so (`saved-incomplete`) instead of "Page saved.", without naming a cause. The fill stops asking once the answers it holds are over 8 MiB in characters, a lower bound of their bytes. The Extension then measures the UTF-8 length of the body it will send and drops trailing answers until the body is at most 8 MiB (`fitThreadBody`, which runs whenever the tab's own `.json` request succeeds, signed in or not); the stubs of the answers left out stay as stubs, which the Reader shows as Context stubs that say they were not saved. A first answer that does not fit alone sends the page fallback instead. The function injected into the tab stops reading an answer at 4 MiB (`Content-Length`, or the stream once it passes the limit) and returns no answer, so an answer over the limit is never transferred to the worker or parsed; the server enforces the same limit in `paste` (413). When the thread's own `.json` request fails, or its answer is not a thread of the post in the link, the worker injects `capture.js` and posts `{url, page}` (the popup says `saved-page`); for a Reddit link the script takes the title from Defuddle's Reddit extractor, because the page's `<title>` ends in the community name.
  - **Connect Reddit (self-hosted builds).** The popup (after a save that left the account expired), the settings page and the Instance's Settings page offer one click. `extension/lib/reddit-account.ts` is the only module that touches the cookie. The worker reads `reddit_session` with `cookies.getAll` and sends it as `{session}` in `PUT /api/reddit-account` with the agent token, which needs the `reddit` scope. The value lives in one local variable of the worker: it is not stored, logged, returned to a page or sent to a content script. The worker sends to the saved Instance origin only, and answers `no-access` and sends nothing when the browser holds no `cookies` permission or no permission for the Instance's host. The network calls run outside the `exclusive` queue that `changeSettings` uses, so a slow Instance never delays a Save or a Fill change. Connect and Disconnect run one at a time in a queue of their own (`oneAtATime` in `extension/lib/one-at-a-time.ts`), whichever surface asks, so a Disconnect from one page cannot overlap a Reconnect from the popup or the Settings relay and leave the Instance's account and the `cookies` permission disagreeing. `cookies` is an optional permission. The settings page requests `cookies` and the Reddit hosts in one `permissions.request` from the click, as its first call, and the worker does the rest. The settings page offers Disconnect in every state while the browser holds `cookies`, and hides the whole Reddit section only when the Instance answers `unavailable` and the browser holds no `cookies`, so a Connect that ended in `signed-out` or `scope-refused` can still give the permission back. Disconnect removes the `cookies` permission when the Instance answers `none` or `missing`, or when no Instance is saved; any other Instance answer keeps the permission and shows the state. The Reddit section shows the answer of the newest request it made. A page load, a refresh after a settings answer and a button press all count as requests. The section ignores the answer of an older request, which can arrive first when the address or the token changed meanwhile. A refresh asked while a button's request runs waits for it, and the section then reads the state once more. The Fill view of the same page follows the same rule. A read that a permission change, or a change of the `fill` flag in `storage.local`, starts replaces an older read, even when the older answer arrives first, so a second open settings page shows the Fill state the first one set. A change that arrives while Turn on or Turn off runs makes one more read afterwards. The rule lives in `newestRequest` and `deferWhileWorking` (`extension/lib/newest-request.ts`). A cookie found in no store is `signed-out`, and more than one cookie of that name is `failed`, because the worker cannot know which one is the session. The Settings relay (`extension/entrypoints/relay.ts`) lets the Instance's Settings page ask the Extension to reconnect: the page posts `{threadsift: "reconnect-reddit", id}` with `window.postMessage`, where `id` is a new UUID, and the content script posts `{threadsift: "reddit-working", id}` once the worker has accepted, and `{threadsift: "reddit-state", id, state}` at the end. The content script accepts only a message from its own window, with the page's own origin and exactly those two fields, and the worker accepts the relay port only from the top frame of a page whose origin is the saved Instance origin. The page waits 3 s (`RELAY_PRESENCE_MS`) for the first of the two, then up to 35 s (`RELAY_RESULT_MS`, above `REDDIT_DEADLINE_MS`, the 30 s after which the relay script disconnects the port and answers `failed`), ignores a message with another `id`, and reads the account state again whatever the answer. The worker accepts its other ports (`save`, `config`, `settings`, `reddit`) only from the Extension's own pages (`fromOwnPage` in `extension/lib/worker-ports.ts`), because the Fill and relay content scripts also pass the `sender.id` check. The relay script is registered with `scripting.registerContentScripts` for the Instance's host on every port, by `syncScripts` (`extension/lib/content-scripts.ts`), for the same reason `fill.js` is. It carries no zod, because a bundled zod adds a `DANGEROUS_EVAL` warning to `web-ext lint`; it checks a message with `src/core/contract/reddit-relay-contract.ts`, which compares own property names and values and imports only the constants of `src/core/contract/reddit-account-state-names.ts`, a module that imports nothing. A Reddit grant that Connect makes does not turn Fill on: `settleFill` (`extension/lib/credentials.ts`) stores `false` the first time the Extension runs without a flag, and stores `false` when a stored `true` has lost its grant, so a later Connect cannot resume a Fill that the Options page showed as off. The worker settles Fill at every start. The owner can withhold the Reddit host on the browser's extension page while the Extension is disabled, and that withholding delivers no `permissions.onRemoved`. Enabling the Extension starts the worker, so the start settles the flag. (Probe, Chromium 156.0.8078.4 under Playwright 1.64.1, 2026-11-16: with the Reddit host withheld while the Extension was disabled, the flag went from `true` to `false` on enable, and a Connect afterwards left Fill off.) Measured on 2026-11-14 with a local Instance and a cookie set by hand (a headless Firefox 160 build of the shipped extension with `extensions.webextOptionalPermissionPrompts` off, and a headless Chromium 157 build whose manifest requires `cookies`): both browsers return the `HttpOnly` cookie to `cookies.getAll`. Chrome throws on the `firstPartyDomain` property, so the Chrome build omits it. Firefox needs it only with `privacy.firstparty.isolate` on, so the Firefox build passes `null`. A cookie in a container tab or a private window, which has its own store, counts as `signed-out`. The dated Extension results record Connect Reddit and account Paste with a real Reddit session. Chrome's own prompt for the optional `cookies` permission, the popup closing while that prompt shows, and a signed Firefox build updated through the store remain unverified. [Extension results](open-items-and-unverified-claims.md).
  - **Fill when opened.** The owner opts in once on the settings page (Fill saved Reddit Items), where Turn on asks the browser for `https://*.reddit.com/*`, one of the optional host permissions the manifest already lists. The opt-in is the grant plus the `fill` flag the background worker stores when the owner presses Turn on or Turn off: the page reads both through the worker, so a revoke in the browser's own settings turns filling off. The worker registers `fill.js` with `scripting.registerContentScripts` for every page of `reddit.com` and its subdomains when the permission is held and removes it when it is not (`syncFillScript`; run at every worker start and on `permissions.onAdded` and `onRemoved`, because MDN says registered scripts are cleared when the extension updates). `fill.js` is an unlisted script, not a WXT `registration: "runtime"` content script, because WXT 0.21.5 adds the `matches` of such a script to the manifest's `host_permissions` (`wxt/dist/internal/manifest.mjs`), which would grant Reddit at install. The script opens one `fill` port when the page's address is a Reddit post or comment, at load and again on each `currententrychange` of the Navigation API (Baseline since January 2026, MDN), which fires for History API navigations, so a thread opened from a feed or from another thread without a page load fills too. The match covers the whole site, because a feed does not match a thread pattern and no script would be there to see the navigation. The worker takes the tab's address from the port's `sender.tab.url`, not `sender.url`, which keeps the address the document loaded with (probe, Chromium under Playwright 1.64.1, 2026-11-10), checks the Instance and Reddit permissions again, asks `GET /api/items?url=<thread link>` and goes on only when an Item has `fillable: true`. Then it reads the thread and sends `{url, content, fill: true}` with the same `send` as Save (`extension/lib/fill.ts`); the body that `fetchThread` returns is the body that is sent, already fitted to the 8 MiB cap with the `fill` field in it. When Reddit access is removed or Turn off is pressed, `cancelFills` aborts every running fill; each checks its signal after the Item lookup, before each permalink read and before it sends, so an answer read before the revoke is not sent, and `answerFor` aborts the injected `fetch` in the tab through a window event named by a per-request token (`cancelInTab`). The cancel can queue behind the read it targets. The tab runs the two injections in the order they were sent, on the page's own thread. The cancel queues behind its read when the page's thread is busy, when the document has not reached `document_idle` (the default time of an injection, Chrome docs, `scripting.executeScript`), or when the read injection is still on its way. Then the read starts its `fetch` and the cancel aborts it right after. That request still reaches Reddit, and the worker drops its answer. So at most one request per running Fill can leave after Turn off. Here "after Turn off" means after the worker runs `cancelFills`, and the page shows Turn off 27 to 191 ms after the press, so a read can also start in between. (Probe, Chromium 156.0.8078.4 under Playwright 1.64.1, 2026-11-16: the page thread of the Reddit tab was blocked with a busy loop for 1.5 s and Turn off was pressed during the block. In 8 of 8 rounds one request reached the stand-in, which the Extension aborted and dropped, and the Item stayed `fillable: true`.) The run that shows no request after Turn off, below, used a tab with an idle page thread. `fillOpenedThread` puts its controller in `filling` before it reads the `fill` flag and `changeSettings` stores the flag before it calls `cancelFills`, so a Fill that starts while Turn off runs either sees the flag off or is cancelled. There is no page fallback, because a page leaves no thread header and the Item would fill again at every visit. Nothing fills in the background: only a thread the owner opens, in a tab, with the Extension opted in. One fill per link runs at a time in the worker; the server decides the rest.
    - **`fillable`.** Every Item view carries it (`FILLABLE_COLUMNS`, `src/core/thread/thread-store.ts`). It is true for a Reddit post or comment that has no `reddit_threads` row for any generation, and false for a thread whose Digest never published. The Reader shows `FILL_NOTE` above the empty text of a `fillable` Item that is not `processing`.
    - **`fill: true`.** `POST /api/items` takes it with `content` only (400 otherwise), and saves the thread only while an Item with this normalized URL exists and has no thread header (`awaitsThread`, `src/core/thread/thread-store.ts`). The check is part of the guard of the batch that writes the thread (`commit`, `src/core/paste/thread-save.ts`), so two fills sent together save once, and an Item that is filled or deleted meanwhile is not written; the answer is 409 `fill: no Item with this link is waiting for its thread` and nothing changes. A guard that fails for this reason is not rebuilt and retried, which would never end.
  - **Other pages.** One press of the toolbar action reads the active tab and posts `{url, page}` with the agent token (`SuppliedPageSchema` in `src/core/contract/supplied-page.ts`). The server never fetches such a page.
- **How the Extension saves a page.** Source: `extension/`, built by `wxt build` (Chrome) and `wxt build -b firefox --mv3`, which are `pnpm run build:extension`. Defuddle is pinned in `pnpm-workspace.yaml` (`catalog:`) to the version the server uses, so the browser and the server read a page alike.
  - **Temporary Firefox install.** After the build, open `about:debugging#/runtime/this-firefox` in Firefox. Choose **Load Temporary Add-on** and open `extension/.output/firefox-mv3/manifest.json`. Firefox removes the temporarily loaded Extension when it restarts. [Firefox Extension Workshop](https://extensionworkshop.com/documentation/develop/temporary-installation-in-firefox/).

    For an unattended load, use the following steps from the repository root. The headless run used geckodriver 0.37.1.

    1. Start `geckodriver --allow-system-access` and set `WEBDRIVER_URL` to the driver's local HTTP address. The switch enables Firefox's privileged browser UI context. [Geckodriver flags](https://firefox-source-docs.mozilla.org/testing/geckodriver/Flags.html#allow-system-access).
    2. Create a WebDriver session. The preference lets a trusted click grant optional permissions during an unattended run. Omit `args` to show a Firefox window.

       ```sh
       session_id=$(curl -fsS "$WEBDRIVER_URL/session" --json \
         '{"capabilities":{"alwaysMatch":{"browserName":"firefox","moz:firefoxOptions":{"args":["-headless"],"prefs":{"extensions.webextOptionalPermissionPrompts":false}}}}}' |
         jq -er '.value.sessionId')
       ```

    3. Run `pnpm --filter threadsift-extension exec wxt zip -b firefox --mv3`. Set `extension_zip` to the absolute path of the Firefox ZIP printed by WXT.
    4. Install the ZIP temporarily using the WebDriver session ID. Check the returned Extension ID against the Gecko ID from `extension/wxt.config.ts`, which WXT writes to the manifest.

       ```sh
       extension_id=$(jq -cn --arg path "$extension_zip" '{path: $path, temporary: true}' |
         curl -fsS "$WEBDRIVER_URL/session/$session_id/moz/addon/install" --json @- |
         jq -er '.value')
       test "$extension_id" = "$(unzip -p "$extension_zip" manifest.json | jq -er '.browser_specific_settings.gecko.id')"
       ```

    5. End the WebDriver session after the check with `curl -fsS -X DELETE "$WEBDRIVER_URL/session/$session_id"`.

  - **Permissions.** The manifest asks for `activeTab`, `scripting` and `storage`, and lists `https` sites and `http` on `localhost` and `127.0.0.1` as optional host permissions, which grant nothing until asked for. The settings page asks for the Instance's host when the owner saves it, so the browser's own prompt names the Instance. A Save has two halves. The page requests the host from the click's user gesture with nothing awaited before the call (Chrome docs, chrome.permissions; MDN, permissions.request), then sends the settings to the background worker, which outlives the page. The worker writes them and then runs `reconcileAccess` (`extension/lib/access.ts`): it keeps the Instance's host and, when Fill is on or `cookies` is held, the Reddit hosts, and removes every other optional host the Extension holds, never one the manifest requires. Only `permissions.request` needs a user gesture, so the worker may call `permissions.remove` (Chrome docs and MDN, permissions.remove). The same reconcile runs after a failed write, after a Fill change, and on `runtime.onStartup` and `runtime.onInstalled`, listeners registered at the top level of the background script (Chrome docs, runtime events and service worker events; MDN, runtime.onStartup and onInstalled). A Save cut short between the grant and the page's message therefore leaves its new host granted until the next browser start or extension update, when the reconcile removes it. The reconcile does not run when the worker is merely woken. A worker start settles Fill and syncs the scripts (the Fill and relay scripts). `permissions.onAdded` only syncs them. A removal also settles Fill and cancels the fills that run. `permissions.onAdded` does not reconcile, because the grant wakes a stopped worker before the page's message arrives, and a reconcile in that gap would remove the host just granted. A removal that fails is named on the page. Saves and Fill changes from several tabs run one after the other in the worker, each from the stored settings read at that moment. `activeTab` gives the press access to the current tab only. The Extension holds no `tabs` or all-sites permission, and `cookies` is optional: the browser asks for it at Connect Reddit, and Disconnect gives it back. A match pattern holds no port (MDN, match patterns), so the grant covers every port on the Instance's host (Chrome docs, activeTab and chrome.permissions; MDN, host_permissions). The Fill saved Reddit Items setting requests `https://*.reddit.com/*` in the same way, from the click on Turn on, and removes it on Turn off unless a Connect grant still needs it (`neededOrigins` in `extension/lib/access.ts`). Before a Reddit grant, the Extension reads Reddit only when a Save runs in a Reddit tab, which reads that tab's thread under `activeTab`.
  - **Capture.** The background worker injects `capture.js`, an unlisted script, into the active tab with `scripting.executeScript`. The script runs Defuddle on the live document, so text a page script added is included, replaces `<video>`, `<audio>` and `<iframe>` with links by the server's `replaceMedia` (`src/core/contract/article-media.ts`), and sets each extracted image's `src` to the `currentSrc` the browser selected and drops its `srcset`, `sizes`, `<picture>` sources and lazy-load attributes, because Defuddle's Markdown otherwise picks the largest `srcset` width (`getBestImageSrc` in Defuddle 0.19.6, `dist/markdown.js`). Shadow DOM and iframe content are not captured.
  - **Token.** The address and the agent token sit in `storage.local`, and the background worker is the only code that reads the token and sends it (`extension/lib/credentials.ts`). The popup and the capture script never see it, and the settings page gets only the address and whether a token exists; a save without a typed token keeps the stored one. The request refuses redirects and ends after 25 s, under the 30 s after which Chrome may stop a worker whose `fetch()` has no response yet (Chrome docs, Extension service worker lifecycle, read 2026-11-09). The address must be `https:`, or `http:` on `localhost` or `127.0.0.1`.
  - **Popup and worker.** A port that closes before an answer shows the failed state (`SaveState` in `extension/lib/state.ts`). The Extension saves with an agent token, so its saves draw on the token's daily budget (see Access, Daily budget); a 429 with `code: budget-spent` shows the `budget-spent` state, and saving works again after 00:00 UTC or when the owner raises the budget in Settings. The worker marks the toolbar button when a save outlives its popup (`serveSave` in `extension/lib/worker-ports.ts`), unless a newer save started before it settled. Each new save clears the mark when its port connects. Opening the popup saves the page again, so a stored last result would have nothing to show. The texts come from `extension/lib/text.ts`, written by `tools/copy/write-copy.sh`.
- **Publishing a sent page.** `POST /api/items` takes `page` as an alternative to `content`; both together answer 400. An X or GitHub link, a short link (`isShortLink`), a Reddit share link (`isRedditShareLink`), a Reddit link that is not a post or comment, and a link `isRefusedLink` refuses never take a page (400), because the Item's identity is the address such a link leads to and a page save resolves nothing: the caller sends the page at that address, or sends the short link alone, which a Paste resolves and records as a Short-link alias ([Short-link aliases](data-model-outline.md#short-link-aliases)); an X link takes its post and replies as `content` instead (Fetchers, X, Supplied thread). A Reddit post or comment link takes it as the Extension's fallback unless the Item holds a saved thread, and stays a Reddit Item (Fetchers, Supplied page). A `page` whose JSON is over 1,000,000 bytes answers 413 and changes nothing, under the same D1 row limit as Large text. Otherwise the page is stored on the Item's fetch job (`jobs.page`) and the job runs the article publication path with the page in place of a network read (`readSuppliedPage` in `src/core/kernel/article.ts`), so the Article or Other rule, the 100-word minimum, the images, the Highlight anchoring and the Digest are the ones a fetched page gets. A save of a link the Item already has refreshes it through the same path. The save closes the Item's open `fetch` and `x_verify` jobs and deletes its `x_verifications` row in the same batch (`closeItemJobs`), so a fetch that was running cannot overwrite the page: its claim is lost and it writes nothing.
- The Threadsift bot's files live in `bot/` and call the same HTTP API and the AI task callbacks. The OpenAPI document from `@hono/zod-openapi` is their contract.
  - **Files.** A template carries skills as text and no other file (the bot's own answer, `docs/architecture/decisions-and-evidence.md`, Grok Bot), so `bot/` holds one skill, `bot/skills/threadsift/SKILL.md` (the bot loads it on every webhook wake, and for another chat turn only when its description matches, so it stays short), and plain files that the skill's bootstrap line installs into `~/threadsift/` on the bot's computer. A template has one profile field (the bot's own answer), and the host uses it for the marketplace card, the share page and the imported bot's profile, so `bot/profile.md` is one description of one or two sentences that names the boundary, and the skill holds the full rules. A template carries no routine, so setup creates the two routines from `bot/routines/`. The skill pins the hash of `SHA256SUMS` and the release tag (`TAG=` and `SUMS_SHA256=` in its bootstrap line) and is not listed in `SHA256SUMS`, because each would then depend on the other; an update trusts the new `SKILL.md` through HTTPS and the tag only.
  - **Webhook tasks.** The body comes from outside, so no value of it becomes a shell word: the bot has no tool that writes a file without the shell, so the agent runs `mark` (it prints a fresh `TS_` and 32 random hex characters) and writes the body with `write event-<hex1>.json <<'TS_<hex1>'`, a heredoc whose delimiter is that word in single quotes. `task-open` parses the file it made with `python3 -I`, checks `taskId`, `callbackToken` and `kind` against fixed patterns (a task id has at most 16 digits and a callback token is 1 to 64 letters, digits, `_` or `-`; the Instance issues `tst_` and 43 characters, `src/core/ai/callback-credential.ts`), answers `already-done` for a task done with that credential and `already-open` for a task that has a `task.json` less than an hour old and no `done`, asks `GET /api/ai-tasks/{id}` with the event's credential, and only when the Instance answers ok makes `tasks/<taskId>/`, so a refused credential leaves the files of an open task as they were. An `x_intake` task is answered with the thread and a Digest through `task-answer`, which posts to the intake route, and the other kinds with a JSON value that fits `schema`, posted to the result route; the server refuses an answer that does not fit with 400 and the reasons, which go to `errors.txt`.
  - **The script.** `bot/scripts/threadsift.sh` reads the Instance address from `THREADSIFT_URL` and the agent token from `THREADSIFT_AGENT_TOKEN`, builds every address from them and sends with `curl --disable` (no `.curlrc`) and `--max-redirs 0`. A link, a query and an answer come from a file that `write` made, and every file argument has to resolve inside `tmp/`; the script deletes each file argument when it ends, whatever it prints. `write` takes a name that matches `^[a-z][a-z0-9-]{0,31}-[0-9a-f]{32}\.(json|txt)$` (the 32 hex characters are those of a `mark`, so `search.json` and `topics.json` can never be written) and at most 8 MiB in total, which protects the disk, since one heredoc call carries far less. `save` prints `ok <id> <path>` with no host because Grok hides any tool output that holds the value of a stored secret and `THREADSIFT_URL` is one. The skill joins the path to the Instance URL that setup keeps as a memory, which is not secret: setup asks the owner to type the address in chat, because a card's value is for the script only. `THREADSIFT_URL` stays a secret card for the script, because a card is how the bot's shell receives a value, and a file that `write` made would need a command and cleanup rules of its own. The owner enters the address twice, so the skill runs `same-address` on the memory before each link, links only after `ok`, asks the owner for the right address on `differs`, and asks for the address when the memory is missing or holds a note. `update.md` (step 1) asks for a missing memory too. `THREADSIFT_URL` is a public address because the bot runs in Grok's cloud and reaches the Instance only there, and it is the address the owner opens. The task credential comes from `tasks/<taskId>/token`, goes to curl through a file descriptor and is in no command line and no output. Each call prints one line that starts with a status word, and `word_of` in the script is the one table that maps a status to a word. An `ok` answer to a `GET` or to `bookmarks-send` whose body is not the JSON the command expects prints `failed` (`shaped` in the script). After `ok` or `closed` the script writes `done` in the task folder, holding the sha256 of the task's credential, and deletes `token`, so a repeated webhook for the same send stops there while a new send of the same task id, which has a new credential, does not. The shell tool of the Grok Bot hands a command to `bash -c` on a file descriptor, so no heredoc body appeared in any process command line there (observed on 2026-11-13: no tty, and `ps -eo args` counted only its own `grep`); a harness that passes the command in argv would expose the event body for the length of the call. One shell call cannot carry a long hand-typed text: a call of about 20,000 characters arrived with no command, twice, and one of about 1,000 characters worked, so the skill limits a `write` or `append` call to 3,000 characters, a size below the smallest failure and not a measured maximum, and the bot reads at most the first 100 replies of an X post, where the intake route takes up to 500. The residual risk is that a heredoc whose delimiter is unquoted or not fresh runs the text as shell before the script starts; the quoting and the fresh word are the only guard. The script checks everything after it: an event, a link, a query or an answer that breaks a check ends `bad-input`. The script needs `python3` and `curl` on the bot's computer, and `setup.md` checks for both. The `failed` word for an Instance that answers 5xx is proven by a run against a real Instance whose database is closed (`test/bot-script-links.test.ts`).
  - **Release.** `tools/bot-release.sh` refreshes `SHA256SUMS` and the hash pinned in `SKILL.md` after an edit of a hashed file (`refresh`, the default), makes a release (`release`: bumps `VERSION`, sets the tag `bot-v<VERSION>`, refreshes, and turns the `## Unreleased` heading of `CHANGELOG.md` into `## bot-v<VERSION>` under a new empty one) or checks both (`check`). Once the tag in `SKILL.md` exists in the repository (`check` and `refresh` fetch it from `origin` when it is not there), `refresh` refuses to run after a change to a hashed file and `check` fails when the pinned hash differs from `SHA256SUMS` at that tag, because the bootstrap line fetches `SHA256SUMS` at the tag and could never match; a change to a hashed file after a release goes through `release`. `test/bot-release.test.ts` runs `check` on the repository, so the gate fails when a change leaves `SHA256SUMS` or the pin out of date. `update.md` finds the newest release from the tags that start with `bot-v` (`GET /repos/KyaniteHQ/threadsift/git/matching-refs/tags/bot-v`), so no GitHub Release object is needed.

They need `python3` and `curl` on the machine, which `devenv.nix` provides, and the listener on `127.0.0.1` that `docs/testing.md` allows.

- **What the manual Chromium run showed (2026-11-15, Chromium 156.0.8078.4, Playwright 1.64.1, Extension 0.1.0, Podman 5.8.9).** A hand-run script, no longer in the repository, loaded the built Extension in Chromium against a local Instance and a local page standing in for Reddit (the stand-in). An answer of 4 MiB minus 8 KiB is saved whole (`saved`). An answer of 4 MiB plus 8 KiB with a `Content-Length` is refused and the page is saved (`saved-page`). A 6 MiB answer with no `Content-Length` is cut after 4,259,840 bytes (the stream passed 4 MiB within one 64 KiB chunk) and the page is saved. A replies answer over 4 MiB is cut at the same point and the thread is saved with 1 of its 2 comments (`saved-incomplete`). Turn off during a Fill, after 3, 5 and 8 requests, answers in 27 to 191 ms and no further request reaches the stand-in in the next 5 s; the Item keeps no thread, because a Fill sends once at the end, and an uninterrupted Fill saves 13 of 13 comments. A Reddit request that the stand-in holds for 3 s is closed 59 ms after Turn off. A thread opened from 80 ms before to 70 ms after Turn off started no Fill in 16 rounds; the same rounds, and a run of 41 rounds from 60 ms before to 60 ms after, found no leak with the earlier code either, so the window is shorter than the run can reach. Of 15 relay messages (an iframe of the Instance's origin, iframes of another port and of `localhost`, a page of another port on the Instance's host, 10 malformed messages), none got a reply or changed the account; the page of another port reached the worker, which refused it. A valid request from the Instance page connects the account. The worker's `frameId` check is not reachable from a page, because the relay script is registered for the top frame only. With the Extension turned off, the no-Extension text appears 3.35 s after the click and not at 2.5 s. The made-up session value appears in no console line, DOM snapshot, posted message, stored value, container log or stand-in path, and in no API answer that a page received; the same scan finds it in the browser's cookie store. - **Deadlines of their calls.** The bot's script sends every call to the Instance with `curl --max-time 60` (`bot/scripts/threadsift.sh`), and the Extension gives every call `REQUEST_DEADLINE_MS`, 25 s (`instanceRequest` in `extension/lib/config.ts`; `send` in `extension/lib/save.ts` uses it for `POST /api/items`). Neither takes the deadline of the web app's Paste, `PASTE_DEADLINE_MS` in `web/src/write-deadlines.ts`, which covers a short link that the Instance resolves inside the request. A bot `add` of a slow short link can therefore end as failed while the Paste still lands on the Instance. A repeat of the `add` only refreshes the Item, because pasting a known link again refreshes it (`docs/spec.md`, Duplicates). The Extension sends the text of a page or a thread, so its request resolves no short link.
