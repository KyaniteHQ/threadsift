# Lint and format

oxlint and oxfmt run directly, not through Vite+. Vite+ 1.5.0 bundles the same oxlint and oxfmt, but its docs advise against `oxlint.config.ts` and `.oxfmtrc.json` and document only `--fix`, `--type-aware` and `-c` for `vp lint` (viteplus.dev/guide/lint, read 2026-11-04). Direct use keeps every oxlint flag and lets oxlint update on its own schedule. `oxlint.config.ts` and `.oxfmtrc.json` hold the rules; what they cannot show:

- **No separate `tsc` step.** `options.typeCheck` makes `oxlint-tsgolint` report TypeScript errors with the lint, and it needs TypeScript 7.
- **Rule plugins in `tools/oxlint/`.** `anti-slop/` is dmmulroy/anti-slop, vendored (its `UPSTREAM.md`); `oxlint.config.ts` and `.oxfmtrc.json` ignore it and `tsconfig.json` excludes it, so the repository's strict options do not apply to upstream code. `threadsift/` holds `no-comments` (`docs/agents/changing-code.md`, No comments), `static-import-source` (`docs/agents/changing-code.md`, Design) and `no-await-before-rethrow` (below). Its folder is exempt from `prefer-readonly-parameter-types`, because ESTree nodes are mutable by construction and no `allow` entry exempts the node types. Anti-slop's `require-safety-comment-for-type-assertion` and its two assertion rules are off, because `typescript/consistent-type-assertions` set to `never` bans the assertion itself, and the safety rule would ask for a comment.
- **`fetch` belongs to `web/src/calls.ts`.** An override in `oxlint.config.ts` refuses the global `fetch` in `web/**` (`no-restricted-globals`) and `globalThis.fetch`, `window.fetch` and `self.fetch` there (`no-restricted-properties`), and excludes `web/src/calls.ts` with `excludeFiles`. A destructured `fetch` is not seen. The Extension and `smoke/` sit outside `web/`, so the rule does not reach them. The reason for the single call module is in `docs/architecture/web-app.md` (Read and write deadlines).
- **`threadsift/no-await-before-rethrow`.** It reports an `await`, a `for await` or an `await using` that runs before a `catch` block throws the caught error, because a failure there replaces the error the caller needs; with `finalizers` on, which `oxlint.config.ts` sets for `src/`, it also reports an `await` in a `finally`. The thrown name resolves through scope to the catch parameter of any enclosing `catch`, and follows `const alias = caught`. An `await` inside a `try` that has a handler passes. The path check is cheap: an `await` in a branch whose own block ends in `return`, `break`, `continue` or `throw` before the rethrow is not reported, and an `await` in a loop body that also holds the rethrow is. A call passes when its callee is bound to a function the `cannotThrow` option names for its declaring module: the option maps a repository path to function names, the rule resolves the callee's import (or its declaration in that module), and it reports a listed name that its own module does not declare, so a stale entry fails lint. A local function with a listed name elsewhere is reported. What it does not see: a nested `catch` that throws, a rethrow of a wrapped error or of any expression other than the caught name, a rethrow inside a helper that the `catch` calls, a `catch` with no parameter or a destructured one, a promise handled with `.then`, and the real exits of a `break` (it treats `break` as the end of the path). The listed functions must catch and log their own failure; nothing checks that.
- **Drizzle types are exempt from `prefer-readonly-parameter-types`.** Its `allow` list in `oxlint.config.ts` names `SQL`, `SQLWrapper`, `SQLiteColumn`, `SQLiteTable` and `Subquery` from `drizzle-orm`, because their members are mutable by construction; a table, column or subquery parameter needs no inline disable. The rule offers no form that matches the named type alone: tsgolint 7.0.2005 also matches any member of an intersection (`TypeMatchesSomeSpecifier` in `internal/utils/type_matches_specifier.go`), so `p: SQL & { extra: string[] }` passes while `p: { extra: string[] }` fails, and a reviewer reads a parameter typed as such an intersection by hand. A disable directive that suppresses nothing is itself an error, so delete a directive when the config starts to cover its line.
- **`ol` and `ul` may carry `role="list"`.** `jsx-a11y/no-redundant-roles` has an `ol` and `ul` exception in `oxlint.config.ts`, because VoiceOver in Safari drops list semantics from a list with `list-style: none` unless the element carries the role.
- **Only safe fixes run unattended.** The commit hook and the agent hook (`.claude/hooks/lint-fix.sh`, after each edit to a file in the project or in one of its git worktrees, linted with that checkout's own `node_modules`) apply safe fixes; suggestion fixes run only through `pnpm lint:fix`, whose diff the agent reads.
- **Markdown is not formatted.** oxfmt pads every table column to its widest cell, so a one-cell change in a doc would rewrite the whole table.
- **`design/` is mostly outside the lint.** `design/prototype/` is reference code, and the CSS in `design/system/` keeps its one-line rule layout, so both stay out of oxlint and oxfmt. `design/system/settings.ts` is app code: oxlint, oxfmt and the TypeScript `include` cover it.
