# Container image

- A `Containerfile` on the official `node:26-slim` image. It runs with Podman or Docker. The `image` and `image-publish` jobs in `.github/workflows/gate.yml` publish it to `ghcr.io/kyanitehq/threadsift` for amd64 and arm64 after every push to `main` that passes the gate (CI, releases and rollback, Image). Version tags are not built. The image is Debian-based, not built by Nix, because the owner's AI CLIs are installed with their vendors' installers, which expect an ordinary Linux root.
- One volume at `/data`: `threadsift.db`, `files/`, `cli/` (the npm prefix, so the CLIs the owner installs) and `claude/` (`CLAUDE_CONFIG_DIR`, where Claude Code keeps its login) and `codex/` (`CODEX_HOME`, mode 0700, where Codex keeps `auth.json`). The `Containerfile` sets `NPM_CONFIG_PREFIX=/data/cli`, `CLAUDE_CONFIG_DIR=/data/claude`, `CODEX_HOME=/data/codex` and puts `/data/cli/bin` on `PATH`, and the `node` user owns `/data`, so the owner installs without root. Anthropic's native installer would also need its own folders in the volume, so the image uses the npm package, which installs the same native binary ([setup](https://code.claude.com/docs/en/setup)).
- The image ships no AI CLI. Claude Code's licence is "SEE LICENSE IN README.md" (npm, 2.1.318), not an open licence, and the CLIs update faster than the image. `docs/guides/providers.md` shows the Claude Code install (`npm install --global @anthropic-ai/claude-code` through `podman exec`, then a restart). The image's npm is 11.20.0 (`podman run --rm <image> npm --version`, 2026-11-07); it prints an `install-scripts` warning for the package and `claude --version` still answers 2.1.319 afterwards. npm 12 skips the postinstall unless allowed, and the guide gives Anthropic's fix ([troubleshoot-install](https://code.claude.com/docs/en/troubleshoot-install#fix-an-npm-12-install)). The guide shows the Codex install the same way (`@openai/codex`, Apache-2.0 on npm, 0.167.0). The Grok install and a derived image are not built. The image installs `ca-certificates`, which `node:slim` lacks: Codex reached no TLS host without it (the first container run answered `unreachable`).
- Public HTTPS comes from the owner's reverse proxy or tunnel; the app listens on plain HTTP inside the container. The operator names that external origin in the environment variable `THREADSIFT_PUBLIC_ORIGIN`, the same name a Worker reads as a variable. The container reads it for OpenRouter Connect (see AI tasks and Providers in `ai-tasks-and-providers.md`).
- Fetcher plug-ins need no `Containerfile` change. The operator sets `THREADSIFT_FETCHERS` (Fetchers, Plug-ins) and mounts the module and everything it imports read-only, for example `-v <host folder>:/fetchers:ro` with `THREADSIFT_FETCHERS=/fetchers/<name>.mjs`. The folder and the files must be readable, and the folders traversable, by the `node` user (uid 1000). Node resolves bare imports from the importing module's own folder, not from `/app/node_modules`, so the module is one bundled file or carries its own `node_modules` beside it. Threadsift installs no package at runtime. The variable is a container variable only: the Worker's variable lists do not name it.
- The Node entry answers a request whose body the app did not read, such as a 401 or a 413 on a body over the cap, only after it has read and discarded that body (`answerAfterBody` in `src/targets/node/unread-body.ts`), so the keep-alive connection stays usable and the client is not reset mid-upload as long as the discard finishes within the two bounds below. A body over the byte cap is the unverified case in Open items and unverified claims. When the client disconnects during the discard, the middleware cancels the response body, so a static file that `serveStatic` opened is closed. Two bounds apply. The discard stops at 64 MiB (`MAX_DISCARD_BYTES`, the value of `MAX_DRAIN_BYTES` in `@hono/node-server` 2.1.5), and past it the response carries `Connection: close`. A client that sends the body too slowly gets Node's own `408` when `server.requestTimeout` runs out (300000 ms by default on Node 26.12.1, `node -p "http.createServer().requestTimeout"`). `@hono/node-server`'s own cleanup of an unread body stops after 500 ms and closes the socket, which reset a client whose next request was already on it.
