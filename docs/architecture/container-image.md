# Container image

- A `Containerfile` on the official `node:26-slim` image, run with Podman or Docker and published as CI, releases and rollback (Image) says. The release workflow publishes version tags for both architectures (`docs/architecture/ci-releases-and-rollback.md`, Releases). The image is Debian-based, not built by Nix, because the owner's AI CLIs are installed with their vendors' installers, which expect an ordinary Linux root.
- One volume at `/data` holds the database, the files, and the install folder and login of each CLI, and the `node` user owns it, so the owner installs without root. The image sets `DATA_DIR=/data`, and the default data folder of `nodeEnvironment`, `/app/.data`, is a link to `/data`, so an empty `DATA_DIR=` or a start without the variable also lands in the volume. Anthropic's native installer would also need its own folders in the volume, so the image uses the npm package, which installs the same native binary ([setup](https://code.claude.com/docs/en/setup)).
- The image ships no AI CLI. Claude Code's licence is "SEE LICENSE IN README.md" (npm, 2.1.318), not an open licence, and the CLIs update faster than the image. `docs/guides/providers.md` shows the Claude Code install (`npm install --global @anthropic-ai/claude-code` through `podman exec`, then a restart). The image's npm is 11.20.0 (`podman run --rm <image> npm --version`, 2026-11-07); it prints an `install-scripts` warning for the package and `claude --version` still answers 2.1.319 afterwards. npm 12 skips the postinstall unless allowed, and `docs/guides/providers.md` gives Anthropic's fix ([troubleshoot-install](https://code.claude.com/docs/en/troubleshoot-install#fix-an-npm-12-install)). `docs/guides/providers.md` shows the Codex install the same way (`@openai/codex`, Apache-2.0 on npm, 0.167.0). `docs/guides/providers.md` shows the grok install (the vendor's `curl -fsSL https://x.ai/cli/install.sh | bash` through `podman exec`, with `HOME=/data/grok` and `GROK_BIN_DIR=/data/grok/bin`: the installer writes the 194 MiB binary to `$HOME/.grok/downloads` and links it into `GROK_BIN_DIR`; probed on the published image with grok 1.0.77, 2026-11-13). The installer needs `curl`, which `node:26-slim` lacks, so the image installs that one package. A derived image is not built. The image installs `ca-certificates`, which `node:slim` lacks: Codex reached no TLS host without it (the first container run answered `unreachable`).
- Public HTTPS comes from the owner's reverse proxy or tunnel; the app listens on plain HTTP inside the container. The operator names that external origin in the environment variable `THREADSIFT_PUBLIC_ORIGIN`, the same name a Worker reads as a variable. The container reads it for OpenRouter Connect (see AI tasks and Providers in `ai-tasks-and-providers.md`).
- `serverOptions` in `src/targets/node/index.ts` sets `keepAliveTimeout` to advertise `Keep-Alive: timeout=65`. Node adds its 1-second buffer and closes the idle socket after 66 seconds. Node 26 defaults to 5 seconds plus that buffer. In two CI traces the document requests ended 5.984 to 5.991 seconds before a save batch reset. A local save reused an idle socket at the same six-second boundary, even when it reached Node directly. Playwright's request agent does not retire a socket based on the advertised timeout, so the smoke stays clear of this race while its sockets stay idle for less than 66 seconds. Set a reverse proxy's upstream idle timeout below the advertised 65 seconds so the proxy closes its connection first. [Node's keep-alive default change](https://github.com/nodejs/node/commit/9f7526984084b7f6d694653eee047cd5b8836ae9) and [Playwright's request agent](https://github.com/microsoft/playwright/issues/42698)
- Fetcher plug-ins need no `Containerfile` change. The operator sets `THREADSIFT_FETCHERS` (Fetchers, Plug-ins) and mounts the module and everything it imports read-only, for example `-v <host folder>:/fetchers:ro` with `THREADSIFT_FETCHERS=/fetchers/<name>.mjs`. The folder and the files must be readable, and the folders traversable, by the `node` user (uid 1000). Node resolves bare imports from the importing module's own folder, not from `/app/node_modules`, so the module is one bundled file or carries its own `node_modules` beside it. Threadsift installs no package at runtime. The variable is a container variable only: the Worker's variable lists do not name it.
- The Node entry answers a request whose body the app did not read, such as a 401 or a 413 on a body over the cap, only after it has read and discarded that body (`answerAfterBody` in `src/targets/node/unread-body.ts`), so the keep-alive connection stays usable and the client is not reset mid-upload as long as the discard finishes within the two bounds below. A body over the byte cap is the unverified case in Open items and unverified claims. Two bounds apply. The discard stops at 64 MiB (`MAX_DISCARD_BYTES`, the value of `MAX_DRAIN_BYTES` in the `@hono/node-server` version `package.json` pins), and past it the response carries `Connection: close`. A client that sends the body too slowly gets Node's own `408` when `server.requestTimeout` runs out (300000 ms by default on Node 26.12.1, `node -p "http.createServer().requestTimeout"`). `@hono/node-server`'s own cleanup of an unread body stops after 500 ms and closes the socket, which reset a client whose next request was already on it.
