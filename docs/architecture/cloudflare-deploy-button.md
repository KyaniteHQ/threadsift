# Cloudflare deploy button

Not built: the README button and `.github/workflows/update-from-upstream.yml`. The deployment command and binding descriptions in `package.json`, `.dev.vars.example`, and the top-level logs configuration in `wrangler.jsonc` are built; a fresh-account deploy, repeat deploy and deployed log redaction still need a live proof.

- The button is `https://deploy.workers.cloudflare.com/?url=https://github.com/KyaniteHQ/threadsift/tree/release`. It points at the `release` branch, which moves only when a release is cut, so a click never deploys work in progress. Cloudflare provisions the resources `wrangler.jsonc` names, which will be the D1 database, R2 bucket, Queue and Workers AI binding (Workers docs, Deploy buttons).
- `.dev.vars.example` lists the secrets the button prompts for: `THREADSIFT_SECRET_KEY` and `SETUP_CODE`. The `bindings` object of the `cloudflare` key in `package.json` explains each binding on that page. `wrangler.jsonc` requires both secrets; Wrangler refuses a deploy that supplies or inherits neither. For a local deploy, copy the example to `.dev.vars`, fill both values, then run `pnpm run deploy --secrets-file .dev.vars`. Keep the encryption key for every later deploy of that Instance. The file stays gitignored.
- `THREADSIFT_PUBLIC_ORIGIN` is a Worker variable, not a secret: the deployed `https://` origin. `wrangler.jsonc` does not hold it, because the origin differs for each deployment and an absent value means no public origin is configured; the deployer sets it as a variable of the Worker. The Worker reads it for OpenRouter Connect (see AI tasks and Providers in `ai-tasks-and-providers.md`).
- `pnpm run deploy` runs `tools/deploy-worker.ts`. It creates a missing named D1 database before applying migrations by binding name, builds the web app, then deploys the Worker. Wrangler provisions the configured R2 bucket and Queue and attaches Workers AI. Existing database ids and names are reused; a failed migration stops the deploy. The script targets the top-level configuration explicitly and preserves Worker variables with `--keep-vars`. `pnpm run deploy --dry-run` builds and checks the Worker without remote operations.
- Top-level `observability` enables Workers Logs and redacts request query strings in `wrangler.jsonc`. The same settings already apply to the live demo.
- The Workers Paid plan ($5 a month) is needed: extracting one 362 KB article page with Defuddle took 236 ms on local workerd (spike, 2026-11-04), and the free plan allows 10 ms of CPU per request (Workers docs, Limits). This is the one place that states the reason; the README says so beside the button once the button exists.
- **Updates.** The button copies the repository into the deployer's own GitHub account, "where they can continue development after deploying", and writes the provisioned resource ids into that copy's `wrangler.jsonc` (Workers docs, Deploy buttons); nothing pulls later releases into the copy. The repository therefore ships `.github/workflows/update-from-upstream.yml` (not built), which runs only outside `KyaniteHQ/threadsift`, weekly or on demand:
  1. It fetches `refs/heads/release` from `https://github.com/KyaniteHQ/threadsift` and lays that tree over the copy's tree, so it needs no shared history.
  2. It writes the copy's own resource ids back into the new `wrangler.jsonc` by binding name, and lists any new binding in the pull request, because Cloudflare has not provisioned it yet.
  3. It opens a pull request with a fine-grained token the deployer adds as `UPDATE_TOKEN` (contents, pull requests and workflows on the copy), because Actions' own `GITHUB_TOKEN` may not change files under `.github/workflows/`. The deployer merges it; Workers Builds deploys the merge, and the deploy script runs the new migrations. Local changes the deployer made show in the pull request's diff.
  4. When a step fails, the run fails and opens an issue in the copy, so a stuck update is visible.

  Every other workflow in the repository runs only when `github.repository == 'KyaniteHQ/threadsift'`, so a copy runs none of the project's gate or release jobs.
