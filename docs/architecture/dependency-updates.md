# Dependency updates

Renovate, the GitHub App, is the one update bot; `renovate.json` holds its rules.

- **Schedule.** Every minor and patch npm update arrives in one PR on Monday morning (Istanbul time); each major gets its own PR, except that `oxlint` and `@oxlint/plugins` always move together, because they must share one exact version. Lock file maintenance refreshes the indirect packages on the first day of each month. The Dependency Dashboard issue lists every pending and waiting update, so it is where an update is noticed. Renovate never merges on its own.
- **Release age.** Renovate proposes an npm version only once it is 3 days old, the same wait as pnpm's `minimumReleaseAge` in `pnpm-workspace.yaml`, so a PR never asks for a version pnpm refuses.
- **Security.** GitHub's Dependabot alerts and the OSV database feed Renovate's security PRs, which open at any time and skip the wait (Renovate docs, `vulnerabilityAlerts`, read 2026-11-04). A fix younger than 3 days still fails pnpm's install, so that PR also adds the package to `minimumReleaseAgeExclude` in `pnpm-workspace.yaml`. Dependabot's own version and security PRs stay off, because both bots would open a PR for the same bump.
- **Local check.** `pnpm outdated` lists the npm updates before Renovate's next run. `devenv.lock` moves through `.github/workflows/update-devenv-lock.yml`, weekly or by hand, because Renovate's `nix` manager reads only `flake.nix` and is still in beta (Renovate docs, Nix manager, read 2026-11-04). The workflow runs `devenv update`, opens a pull request and approves the `pull_request` runs of `gate` and `bundle` on its head through the REST endpoint for approving a workflow run, polling until both have appeared and failing with the name of one that never starts, because a pull request that `GITHUB_TOKEN` opens holds its `pull_request` runs for approval (GitHub docs, Triggering a workflow from a workflow, read 2026-11-04). A `gate` started with `workflow_dispatch` instead passed but left the pull request blocked on `main`'s required check while the held run waited (a throwaway pull request, 2026-11-04). The approve endpoint needs the Actions write permission, which the job's `actions: write` gives its `GITHUB_TOKEN` (GitHub REST docs, Permissions required for GitHub Apps, read 2026-11-04). It needs the repository setting that lets Actions create pull requests.
- **devenv CLI.** `.github/actions/setup-devenv` installs the `devenv` CLI from the `nixpkgs` input that `devenv.lock` pins, which `jq` reads from the lock's root node, so the CLI moves with the weekly `devenv.lock` update and can trail a devenv release by up to a week. Renovate has no devenv rule. The action needs that input to be a `github` input. The locked `cachix/devenv-nixpkgs` ships devenv 2.4.0 (`nix eval --raw github:cachix/devenv-nixpkgs/<rev>#devenv.version`) from `cache.nixos.org` (`nix path-info --store https://cache.nixos.org <outPath>`, 2026-11-10), and the shell evaluation needs that nixpkgs anyway, so the install adds no source tree of its own (CI, Nix input downloads).
