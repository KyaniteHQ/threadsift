# Threadsift security model

Reviewed `KyaniteHQ/threadsift` at `5193796b`. Threadsift is a self-hosted, single-owner reading library. The code supports a Node container with SQLite and a persistent data volume, and a Cloudflare Worker with D1, R2, a Jobs queue, and Cron. The container quickstart publishes to loopback. A reverse proxy or tunnel can expose it to other devices. The Worker configuration has separate bindings for its live environment. This model covers both install targets and uses repository deployment configuration. [Install guide](https://github.com/KyaniteHQ/threadsift/blob/5193796b/docs/guides/self-hosting.md) · [Install architecture](https://github.com/KyaniteHQ/threadsift/blob/5193796b/docs/architecture/one-codebase-two-install-targets.md) · [Worker configuration](https://github.com/KyaniteHQ/threadsift/blob/5193796b/wrangler.jsonc)

## Components and trust boundaries

| Component | Boundary and code |
| --- | --- |
| Library and Reader | The owner’s browser displays saved posts, comments, Digests, and media. Treat source content and links as untrusted even after they are stored. `web/src/`, `src/features/item/`, `src/features/media/`, `src/features/wiki/`. |
| Instance Access | The HTTP API handles owner sessions and scoped bearer tokens. It also serves the Web Share Target and agent-token MCP. First-run setup and password reset depend on operator-controlled codes. `src/http/`, `src/features/access/`. |
| Link Ingestion | Pasted links, Extension captures, imports, remote redirects and fetched content cross into the Instance. Fetch and parse jobs call external sites and bring content into storage. Container fetcher plug-ins run operator-installed code. `src/features/paste/`, `src/features/fetch/`, source-specific fetchers, `src/core/kernel/fetch-guard.ts`, target networking adapters. |
| Agent and Integrations | The Instance sends saved material to the configured Provider and validates results. Grok Bot uses a webhook and scoped callback credentials. The Extension handles the owner’s browser context and an agent token. The optional Obsidian vault mirror crosses into a local folder or GitHub. `src/features/ai/`, `src/features/digest/`, `src/features/bot/`, `src/features/vault/`, `extension/`, `bot/`, and target Provider adapters. |
| Storage and Jobs | Runtime jobs and their inputs cross into the database and object or file store. Export and Restore move entire libraries across an archive boundary. `src/core/compose/`, `src/core/kernel/backup-tables.ts`, `src/features/export/`, `src/features/restore/`, `migrations/`, and the target storage adapters. |
| Deployment and Release | The Instance operator controls boot configuration, secrets, and network exposure. GitHub Actions build and publish release artifacts or deploy the Worker. `Containerfile`, `wrangler.jsonc`, `.github/workflows/`, `tools/deploy-worker.ts`, and the Node and Worker entry points. |

## Who can reach the entry points

- An unauthenticated network caller can reach sign-in, session checks, and setup or reset paths on an exposed Instance. Setup and reset depend on their respective codes. The documented account model has one owner per Instance. [Access and interfaces](https://github.com/KyaniteHQ/threadsift/blob/5193796b/docs/spec.md#access)
- An owner session can read and change library state, configure integrations and tokens, and use Export or Restore. The Web Share Target at `/share` requires an owner session and same-origin browser signals. [HTTP interfaces](https://github.com/KyaniteHQ/threadsift/blob/5193796b/docs/architecture/http-interfaces.md)
- An authorized or compromised agent token can use the Item API or `/mcp` within its scopes. A token with read access can see private Item data. A token allowed to add Items can submit source material and queue work. Each agent token has a daily budget for new Items. Task credentials for `/api/ai-tasks/{id}` are separate and bound to the task. [Agent tokens](https://github.com/KyaniteHQ/threadsift/blob/5193796b/docs/spec.md#token-scopes) · [Grok Bot routes](https://github.com/KyaniteHQ/threadsift/blob/5193796b/docs/architecture/http-interfaces.md#the-grok-bot-task-routes)
- A remote publisher, redirector, or integration can influence fetched content, metadata, media, and model input without owning a Threadsift account. The content enters when an authorized caller saves or imports it. Operators and deployment identities control more privileged inputs, including configuration, storage, installed plug-ins, and releases. [Fetchers](https://github.com/KyaniteHQ/threadsift/blob/5193796b/docs/architecture/fetchers.md) · [CI and releases](https://github.com/KyaniteHQ/threadsift/blob/5193796b/docs/architecture/ci-releases-and-rollback.md)

## Assets and existing controls

- **Private library content and integrity.** Saved links, source text, media, Highlights, Notes, Digests, and the wiki reveal the owner’s reading activity. An Export contains library records and files but excludes credentials and session or token hashes. The export routes require the owner session. The Reader renders source Markdown without raw HTML, and the browser document has a restrictive CSP. [Export and Restore](https://github.com/KyaniteHQ/threadsift/blob/5193796b/docs/architecture/export-backup-and-restore.md) · [Reader Markdown](https://github.com/KyaniteHQ/threadsift/blob/5193796b/web/src/PostText.tsx) · [Browser headers](https://github.com/KyaniteHQ/threadsift/blob/5193796b/src/http/web-headers.ts)
- **Credentials and owner authority.** The owner password, session cookies, setup and reset codes, agent tokens, task credentials, the Instance encryption key, and Provider, Reddit, and GitHub credentials protect access. Cookies are host-prefixed, Secure, HttpOnly, and SameSite=Lax. Route policies declare credential and origin checks. Saved integration secrets are sealed under the Instance key. The configured Provider or integration receives only the data each flow sends to it, so those flows establish external confidentiality boundaries. [Route controls](https://github.com/KyaniteHQ/threadsift/blob/5193796b/src/http/access-steps.ts) · [Cookies](https://github.com/KyaniteHQ/threadsift/blob/5193796b/src/http/session-cookie.ts) · [Secret key](https://github.com/KyaniteHQ/threadsift/blob/5193796b/docs/guides/self-hosting.md#keep-the-secret-key)
- **Host, network, and processing resources.** Keep link ingestion away from private network services and preserve job capacity and Provider spend. Built-in fetch paths use a shared guard with redirect, time, and byte limits. The Node network adapter checks the destination addresses used for connections. Worker egress follows a separate adapter and environment. The container’s Claude Code and Codex adapters restrict model tool access and run with a minimal environment. [Fetch controls](https://github.com/KyaniteHQ/threadsift/blob/5193796b/docs/architecture/fetchers.md) · [AI tasks and Providers](https://github.com/KyaniteHQ/threadsift/blob/5193796b/docs/architecture/ai-tasks-and-providers.md)

## Priorities and open questions

The owner confirmed that private library content and exports, Instance credentials and owner access, and the host and its private network are critical. The owner kept the submitted audit priorities, which emphasize private library data, credentials, and untrusted link ingestion, and specified no accepted risks or exclusions. The owner asked to cover both install targets and leave actual internet exposure unconfirmed.

Keep anonymous network callers, compromised scoped credentials, malicious content sources, and compromised integrations in scope. Live proxy configuration and enabled integrations are open questions. The repository documents a future hosted product outside the current single-owner implementation. This model uses the deployment configuration inside Threadsift and has no separate infrastructure repository.
